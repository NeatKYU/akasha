# Effect가 필요 없는 경우 판별 기준

## 출처

- 출처 id: `react-effect-avoidance`
- URL: https://react.dev/learn/you-might-not-need-an-effect
- 소유자: Meta
- 권위: primary
- 라이선스 메모: 메타데이터, 링크, 짧은 출처 표기 요약만 사용한다. 원문을 복제하지 않는다.
- 사용 메모: Effect 남용 판정과 대안 제시에만 사용한다.
- 검토 스냅샷: `react-effect-avoidance` 구조 `15162b5a4f59` 본문 `8194cab734dc`

## 이 문서가 해당 역할에 도움이 되는 이유

React 앱의 성능 문제 대부분은 Effect에서 시작된 갱신 연쇄에서 나온다. 그런데 "이 useEffect는
없어도 된다"는 판정은 근거 없이 내리면 취향 논쟁이 된다. 공식 문서는 Effect가 불필요한 경우를
유형별로 규정하고 각각의 대안을 지정하므로, 프론트엔드 에이전트가 위반과 대안을 함께 제시할 수 있다.

핵심 갈림길은 하나다. **"컴포넌트가 화면에 표시되었기 때문에" 실행되어야 하는가, 아니면
"사용자가 무언가 했기 때문에" 실행되어야 하는가.** 후자는 Effect가 아니라 이벤트 핸들러다.

## 프로젝트에 적용할 기준

- props나 state에서 계산할 수 있는 값은 Effect와 state로 옮기지 않고 렌더 중에 계산한다.
- 비싼 계산은 Effect가 아니라 `useMemo`로 감싼다. 비싼지 여부는 `console.time` 같은 측정으로 판단한다.
- prop이 바뀔 때 state 전체를 초기화하려면 Effect가 아니라 `key`로 컴포넌트를 분리한다.
- prop 변화에 따라 일부 state만 조정할 때는 이전 prop을 state로 보관해 렌더 중에 조정하거나, 값을 파생시킨다.
- 특정 사용자 동작 때문에 실행되어야 하는 로직은 Effect가 아니라 이벤트 핸들러에 둔다. 여러 핸들러가 공유하면 함수로 추출한다.
- Effect가 state를 바꿔 다음 Effect를 트리거하는 연쇄를 만들지 않는다. 다음 state는 이벤트 핸들러에서 한 번에 계산한다.
- 외부 스토어 구독은 수동 `addEventListener` + Effect 대신 `useSyncExternalStore`를 쓴다.
- 자식 state 변화를 부모에게 알릴 때 Effect로 콜백을 호출하지 않고 같은 이벤트 핸들러에서 함께 호출한다.
- Effect에서 데이터를 가져올 때는 정리 함수로 오래된 응답을 무시해 경쟁 상태(race condition)를 막는다.

## 주의할 점

- 데이터 페칭 자체는 Effect의 정당한 용도다. 문제는 정리 함수 없이 쓰는 것이다.
- 렌더 중 state 조정은 **같은 컴포넌트의 state**에만 쓸 수 있고 즉시 재렌더를 유발한다. 파생값이나 `key`로 해결되면 그쪽을 먼저 쓴다.
- `key`로 초기화하면 DOM이 다시 만들어지고 하위 state가 전부 초기화된다. 의도한 범위인지 확인한다.
- 앱 초기화 로직은 개발 모드에서 두 번 실행될 수 있어 모듈 수준 플래그나 모듈 초기화 시점 실행이 필요하다.
- React Compiler가 자동 메모이제이션을 하는 환경에서는 수동 `useMemo`·`useCallback` 지적의 값어치가 줄어든다. 프로젝트 설정을 먼저 확인한다.

## 에이전트가 사용할 때의 체크리스트

- 이 Effect가 하는 일을 props나 state에서 렌더 중 계산으로 대체할 수 있는가?
- 이 로직이 실행되는 이유가 "사용자가 무언가 했기 때문"인가? 그렇다면 이벤트 핸들러로 옮길 수 있는가?
- Effect가 자기 의존성에 포함된 state를 갱신해 연쇄나 무한 루프를 만들지 않는가?
- prop 변화에 따른 초기화를 `key`로 표현할 수 있는가?
- 외부 시스템 구독이라면 `useSyncExternalStore` 대신 수동 구독을 쓸 이유가 있는가?
- 데이터를 가져오는 Effect에 오래된 응답을 무시하는 정리 함수가 있는가?
- 비싼 계산이라는 주장에 측정 근거가 있는가?
