# 렌더 성능 측정 기준

## 출처

- 출처 id: `react-profiler`
- URL: https://react.dev/reference/react/Profiler
- 소유자: Meta
- 권위: primary
- 라이선스 메모: 메타데이터, 링크, 짧은 출처 표기 요약만 사용한다. 원문을 복제하지 않는다.
- 사용 메모: 렌더 성능 주장의 측정 근거 판정에만 사용한다.
- 검토 스냅샷: `react-profiler` 구조 `54e828d4d65d` 본문 `e1c75794978f`

## 이 문서가 해당 역할에 도움이 되는 이유

"최적화했더니 빨라졌다"는 주장은 측정 없이는 검증할 수 없다. `Profiler`는 렌더 시간을
실제 수치로 남기고 메모이제이션이 실제로 작동하는지 보여준다. 데이터 역할이 EXPLAIN을
요구하듯, 프론트엔드도 이 근거를 요구할 수 있다.

## 프로젝트에 적용할 기준

- 렌더 성능 개선 주장에는 `actualDuration` 전후 수치를 남긴다.
- 메모이제이션이 실제로 작동하는지는 `actualDuration`과 `baseDuration`의 차이로 확인한다.
- `phase`로 mount와 update를 구분해 비교한다. 초기 마운트 비용을 갱신 비용과 섞지 않는다.
- 측정은 필요한 구간에만 두고 끝나면 제거한다.

## 주의할 점

- profiling은 CPU·메모리 오버헤드를 더한다. 상시 계측으로 두지 않는다.
- production 빌드에서는 기본적으로 비활성이다. 별도 profiling 빌드가 필요하다.
- `baseDuration`은 최적화가 전혀 없을 때의 추정치이지 실제 측정이 아니다.

## 에이전트가 사용할 때의 체크리스트

- 성능 개선 주장에 렌더 시간 전후 수치가 있는가?
- mount와 update를 구분해 비교했는가?
- `actualDuration`이 `baseDuration`보다 충분히 낮아 최적화가 실제로 작동함을 보이는가?
- 계측 코드가 임시인가, 아니면 상시로 남아 오버헤드를 더하고 있는가?
