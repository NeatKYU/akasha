# useMemo 사용 판단 기준

## 출처

- 출처 id: `react-usememo`
- URL: https://react.dev/reference/react/useMemo
- 소유자: Meta
- 권위: primary
- 라이선스 메모: 메타데이터, 링크, 짧은 출처 표기 요약만 사용한다. 원문을 복제하지 않는다.
- 사용 메모: 비싼 계산 캐싱 판단과 잘못된 useMemo 사용 판정에만 사용한다.
- 검토 스냅샷: `react-usememo` 구조 `646e8ac829f7` 본문 `4dbf2e8df58e`

## 이 문서가 해당 역할에 도움이 되는 이유

`useMemo`는 붙이면 빨라지는 장치가 아니다. 값어치가 있는 조건이 좁고, 조건을 벗어나면
코드만 복잡해진다. 공식 레퍼런스는 그 조건과 측정 방법, 그리고 useMemo가 하지 **않는**
일을 규정하므로 근거 없는 최적화를 지적할 수 있다.

## 프로젝트에 적용할 기준

- `useMemo`는 세 경우에만 값어치가 있다 — 계산이 실제로 비싸고 의존성이 자주 안 바뀔 때, `memo` 자식에게 넘길 값일 때, 다른 훅의 의존성일 때.
- 비싼지 여부는 `console.time`으로 측정한다. 상호작용당 1ms 미만이면 비싸지 않다.
- 측정은 production 빌드에서, 대상 사용자와 비슷한 기기 또는 CPU 스로틀링 조건으로 한다.
- 계산 안에서 참조하는 모든 반응형 값을 의존성에 넣고, 배열 길이를 고정한다.
- 의존성으로 쓸 객체는 그 객체 자체를 `useMemo`로 감싼다. 매 렌더 새로 만들면 무한 재계산이 된다.
- 계산은 순수해야 한다. props를 변형하지 않고, 새로 만든 객체만 변형한다.
- `useMemo` 없이 코드가 동작하지 않으면 최적화가 아니라 버그다. 원인을 먼저 고친다.

## 주의할 점

- React는 캐시를 언제든 버릴 수 있다. 캐싱을 의미 보장으로 삼지 않는다.
- 첫 렌더는 빨라지지 않는다. 갱신에만 도움이 된다.
- 컴포넌트 자신의 리렌더를 막지 않는다. 자식 리렌더를 막으려면 `memo`와 짝이어야 한다.
- Strict Mode 개발 환경에서 계산이 두 번 실행된다. 순수하면 결과에 영향이 없다.
- React Compiler를 쓰는 환경에서는 수동 `useMemo` 지적의 값어치가 줄어든다.

## 에이전트가 사용할 때의 체크리스트

- 이 `useMemo`가 세 가지 조건 중 어디에 해당하는가?
- 비싸다는 주장에 측정 근거가 있는가?
- 의존성에 매 렌더 새로 만들어지는 객체가 들어 있지 않은가?
- 계산이 순수한가? props를 변형하지 않는가?
- `useMemo`를 지우면 동작이 깨지는가? 그렇다면 최적화 문제가 아니다.
