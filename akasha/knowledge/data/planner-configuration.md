# 플래너 설정 변경 기준

## 출처

- 출처 id: `postgres-runtime-query`
- URL: https://www.postgresql.org/docs/current/runtime-config-query.html
- 소유자: PostgreSQL Global Development Group
- 권위: primary
- 라이선스 메모: 메타데이터, 링크, 짧은 출처 표기 요약만 사용한다. 원문을 복제하지 않는다.
- 사용 메모: 플래너 파라미터 조정의 진단 목적과 운영 반영 판정에만 사용한다.
- 검토 스냅샷: `postgres-runtime-query` 구조 `b77bdd64c4ca` 본문 `e98b24c8aaeb`

## 이 문서가 해당 역할에 도움이 되는 이유

`enable_seqscan = off` 같은 설정은 진단에 유용하지만 운영 설정으로 남으면 다른 쿼리를
망가뜨린다. 공식 문서가 이 파라미터들을 "임시 진단 수단"으로 명시하고 더 나은 대안을
제시하므로, 설정 변경 제안의 성격을 가려낼 수 있다.

## 프로젝트에 적용할 기준

- `enable_*` 파라미터는 **임시 진단 수단**이다. 세션 범위에서 비교에만 쓰고 운영 설정으로 남기지 않는다.
- 계획이 나쁘면 파라미터를 끄기 전에 `ANALYZE` 재실행, 통계 목표 상향, 컬럼별 통계 조정을 먼저 시도한다.
- 비용 상수는 상대값만 의미가 있다. 전체를 같은 비율로 바꾸는 것은 효과가 없다.
- `random_page_cost`·`effective_cache_size` 같은 값을 바꾼다면 몇 개 쿼리가 아니라 전체 쿼리 조합을 근거로 한다.
- 운영 설정 변경 제안에는 어떤 쿼리 집합에서 어떻게 검증했는지 함께 적는다.

## 주의할 점

- 비용 상수의 이상값을 정하는 정해진 방법은 없다. 몇 번의 실험으로 바꾸는 것은 위험하다고 문서가 명시한다.
- `enable_*`를 끈 상태의 실행 계획은 "이 계획이 가능했다"는 정보이지 "이 계획이 낫다"는 증거가 아니다.
- 이 문서는 설정을 다룬다. 실행 계획 판독은 실행 계획 문서를, 인덱스 검증 절차는 인덱스 문서를 본다.

## 에이전트가 사용할 때의 체크리스트

- 파라미터 변경이 진단 목적인가, 운영 반영 제안인가?
- 운영 반영이라면 통계 개선을 먼저 시도했는가?
- 비용 상수 변경 근거가 전체 쿼리 조합에 기반하는가, 몇 개 사례인가?
- 세션에서 끈 설정이 운영 구성에 남지 않는가?
