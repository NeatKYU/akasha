# WCAG 2.2 적합성 판정 기준

## 출처

- 출처 id: `wcag-22`
- URL: https://www.w3.org/TR/WCAG22/
- 소유자: W3C
- 권위: primary
- 라이선스 메모: 메타데이터, 링크, 짧은 출처 표기 요약만 사용한다. 원문을 복제하지 않는다.
- 사용 메모: 접근성 적합성 주장의 범위와 수준 판정에만 사용한다.
- 검토 스냅샷: `wcag-22` 구조 `1cc56727c4bc` 본문 `64fd73cdb772`

## 이 문서가 해당 역할에 도움이 되는 이유

"접근성을 개선했다"는 주장은 범위와 수준을 밝히지 않으면 검증할 수 없다. WCAG는 네 원칙,
세 수준, 다섯 가지 적합성 요구사항으로 그 주장을 구조화하므로 무엇이 빠졌는지 물을 수 있다.

## 프로젝트에 적용할 기준

- 적합성 주장은 수준(A / AA / AAA)과 대상 범위를 함께 밝힌다.
- 적합성은 페이지 단위다. 일부 영역만 고쳤다면 페이지가 적합하다고 말하지 않는다.
- 여러 단계를 거치는 절차는 전 과정이 적합해야 한다. 한 단계만 고친 것은 절차 적합이 아니다.
- AA를 목표로 하면 A와 AA의 모든 성공 기준을 만족해야 한다. 대표적으로 대체 텍스트, 자막, 키보드 조작과 보이는 포커스, 본문 대비 4.5:1, 200% 확대 시 기능 유지, 의미 있는 제목 구조, 폼 레이블과 오류 식별이 포함된다.
- 접근성 지원 기술만 사용한다. 보조기술이 해석하지 못하는 방식은 적합성 근거가 되지 않는다.
- 비간섭 요구사항에 따라, 적합 대상이 아닌 콘텐츠도 페이지 전체 사용을 방해해서는 안 된다.

## 주의할 점

- 자동 검사 도구 통과는 적합성 증명이 아니다. 상당수 기준은 사람이 판단해야 한다.
- 제3자 콘텐츠나 특정 언어처럼 통제 밖 요소가 있으면 부분 적합 성명이라는 별도 형식이 있다. 전체 적합으로 뭉뚱그리지 않는다.
- AAA는 일부 콘텐츠에서 달성 불가능할 수 있어 전체 정책 목표로 두지 않는 것이 일반적이다.

## 에이전트가 사용할 때의 체크리스트

- 적합성 주장에 수준과 범위가 명시되어 있는가?
- 페이지 전체가 아니라 일부 컴포넌트만 고치고 페이지 적합을 주장하지 않는가?
- 여러 단계 절차라면 전 과정이 검토되었는가?
- 대비, 키보드 조작, 포커스 표시, 폼 레이블, 오류 식별이 확인되었는가?
- 자동 검사 결과만으로 적합을 주장하지 않는가?
