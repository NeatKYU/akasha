- 사용 메모: 로그인·비밀번호·계정 잠금·재인증 판정에만 사용한다.

## 이 문서가 해당 역할에 도움이 되는 이유

인증은 구현이 흔한 만큼 실수도 반복된다. 오류 메시지로 계정 존재가 드러나거나, 잠금 정책이
없거나, 민감 작업에 재인증이 없는 경우가 대표적이다. OWASP 기준은 각각을 확인 가능한
형태로 규정하므로 위반을 위치와 함께 지목할 수 있다.

## 프로젝트에 적용할 기준

- 로그인 실패 응답은 계정 존재 여부와 무관하게 동일하다. 메시지·상태 코드·응답 시간이 모두 같아야 한다.
- 비밀번호는 해시로 저장하고, 조용한 절단 없이 충분한 최대 길이를 허용한다. 유니코드와 공백을 허용한다.
- 유출 이력이 있는 비밀번호를 차단하고, 주기적 강제 변경 대신 강한 비밀번호와 MFA를 유도한다.
- 계정 잠금 카운터는 IP가 아니라 계정에 붙인다. 임계값·관찰 구간·잠금 시간을 명시한다.
- 비밀번호 변경, 이메일 변경, 결제 같은 민감 작업에는 재인증을 요구하고 이후 세션 토큰을 회전한다.
- 이메일 변경은 기존 주소와 새 주소 **양쪽**에 확인을 보낸다.
- 인증 실패와 계정 잠금을 로그로 남긴다.

## 주의할 점

- 계정 단위 잠금은 공격자가 임의 계정을 잠글 수 있는 서비스 거부 경로가 된다. 복구 수단을 함께 둔다.
- MFA가 있어도 인증 자체의 결함을 대신 막아주지 않는다.
- 이 문서는 인증을 다룬다. 권한 판정은 인가 기준 문서를, 입력 검증은 입력 검증 문서를 근거로 한다.

## 에이전트가 사용할 때의 체크리스트

- 로그인 실패 응답이 계정 존재 여부를 드러내지 않는가?
- 비밀번호 최소·최대 길이와 허용 문자 범위가 코드로 강제되는가?
- 계정 잠금 임계값·관찰 구간·잠금 시간이 정의되어 있는가?
- 민감 작업에 재인증과 토큰 회전이 있는가?
- 이메일 변경이 양쪽 주소에 확인을 보내는가?
- 인증 실패가 로그로 남는가?
