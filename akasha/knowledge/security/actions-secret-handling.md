# Actions 비밀값 취급과 스크립트 주입 방지

## 출처

- 출처 id: `gh-actions-secure-use`
- URL: https://docs.github.com/en/actions/reference/security/secure-use
- 소유자: GitHub
- 권위: primary
- 라이선스 메모: 메타데이터, 링크, 짧은 출처 표기 요약만 사용한다. 원문을 복제하지 않는다.
- 사용 메모: 워크플로의 비밀값 처리, 스크립트 주입, 액션 고정 판정에만 사용한다.
- 검토 스냅샷: `gh-actions-secure-use` 구조 `6bbca9162fbf` 본문 `66741fec3093`

## 이 문서가 해당 역할에 도움이 되는 이유

CI 워크플로는 신뢰할 수 없는 입력이 권한 있는 컨텍스트로 들어오는 대표적인 지점이다.
이슈 제목 하나가 셸 명령으로 해석되면 저장소 전체가 넘어간다. 공식 레퍼런스가 비밀값
취급과 주입 방지 방법을 규정하므로 위반을 구체적으로 지목할 수 있다.

## 프로젝트에 적용할 기준

- 비밀값에서 파생·변환한 값(생성한 JWT, 인코딩 결과)도 secret으로 등록해 마스킹되게 한다.
- JSON·YAML 같은 구조화 데이터를 하나의 secret에 담지 않고 개별 secret으로 나눈다.
- 신뢰할 수 없는 컨텍스트 값(`github.event.*`)을 셸 명령에 직접 보간하지 않는다. 중간 환경 변수에 담고 따옴표로 감싼다.
- 기본 `GITHUB_TOKEN` 권한을 읽기 전용으로 두고 필요한 잡에서만 올린다. 올린 이유를 남긴다.
- 제3자 액션은 40자 전체 커밋 SHA로 고정한다. 태그는 immutable하지 않다.
- 고정한 SHA가 포크가 아니라 공식 저장소에서 왔는지 확인한다.
- 테스트 후 워크플로 로그를 직접 확인해 비밀값이 노출되지 않았는지 본다.

## 주의할 점

- `pull_request_target`과 `workflow_run`은 권한 있는 컨텍스트에서 돈다. 신뢰할 수 없는 PR 코드를 checkout하지 않는다.
- self-hosted runner는 깨끗한 임시 VM을 보장하지 않는다. 공개 저장소에는 쓰지 않는다.
- 잡끼리 Docker 소켓·디렉터리·환경 변수를 통해 서로에게 영향을 줄 수 있다. 액션 하나가 뚫리면 모든 secret에 닿을 수 있다.

## 에이전트가 사용할 때의 체크리스트

- 파생된 민감값이 secret으로 등록되어 마스킹되는가?
- `github.event.*` 값이 `run:` 안에 직접 보간되어 있지 않은가?
- `GITHUB_TOKEN` 기본 권한이 읽기 전용인가?
- 제3자 액션이 전체 커밋 SHA로 고정되어 있는가?
- 권한 있는 트리거가 신뢰할 수 없는 코드를 checkout하지 않는가?
- self-hosted runner가 공개 저장소에 노출되어 있지 않은가?
