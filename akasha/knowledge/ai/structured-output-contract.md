# 구조화 출력 계약 기준

## 출처

- 출처 id: `openai-structured-outputs`
- URL: https://developers.openai.com/api/docs/guides/structured-outputs
- 소유자: OpenAI
- 권위: primary
- 라이선스 메모: 메타데이터, 링크, 짧은 출처 표기 요약만 사용한다. 원문을 복제하지 않는다.
- 사용 메모: 에이전트 반환 형식을 스키마로 강제할지 판정에만 사용한다.
- 검토 스냅샷: `openai-structured-outputs` 구조 `91d03d79dfd4` 본문 `729176df66ea`

## 이 문서가 해당 역할에 도움이 되는 이유

아카샤의 서브에이전트는 `classification`·`location`·`basis` 같은 필드로 판정을 반환하도록
계약돼 있지만, 이 계약은 지금 프롬프트로만 요구된다. 구조화 출력은 그 계약을 스키마로
강제하는 수단이며, 무엇을 보장하고 무엇을 못 하는지 공식 문서가 규정한다.

## 프로젝트에 적용할 기준

- 반환 형식이 계약인 곳에서는 JSON 모드가 아니라 스키마 준수를 강제하는 구조화 출력을 쓴다. JSON 모드는 문법만 보장한다.
- 루트는 객체여야 하고 `anyOf`일 수 없다. 모든 필드를 required로 두고 객체마다 `additionalProperties: false`를 설정한다.
- 선택적 필드는 생략이 아니라 `null`을 포함한 유니온 타입으로 표현한다.
- 중첩 깊이·속성 수·enum 개수 상한이 있으므로 스키마를 설계할 때 확인한다.
- 거절 응답은 스키마를 따르지 않고 별도 필드로 온다. 이 경우를 코드에서 구분해 처리한다.

## 주의할 점

- `allOf`, `not`, `if/then/else`, `dependentRequired` 는 지원되지 않는다. 스키마를 그에 맞게 설계한다.
- 파인튜닝 모델은 문자열 길이·패턴·숫자 제약 등 일부를 추가로 지원하지 않는다.
- 스키마 준수는 형식 보장이지 내용의 정확성 보장이 아니다. 판정의 옳고 그름은 별도로 검증한다.

## 에이전트가 사용할 때의 체크리스트

- 반환 형식이 계약이라면 스키마로 강제되고 있는가, 프롬프트 요구뿐인가?
- 모든 필드가 required이고 `additionalProperties: false`인가?
- 선택적 필드를 null 유니온으로 표현했는가?
- 거절 응답 경로가 코드에서 구분되는가?
- 스키마 준수를 내용 정확성으로 착각하고 있지 않은가?
