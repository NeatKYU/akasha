- 소유자: OpenAI
- 권위: primary

- 사용 메모: 에이전트 프롬프트 구성이 캐시 재사용을 깨뜨리는지 판정에만 사용한다.
- 검토 스냅샷: `openai-prompt-caching` 구조 `c7c967ba8043` 본문 `e1ab7d33de7e`

## 이 문서가 해당 역할에 도움이 되는 이유

에이전트 토큰 비용의 상당 부분은 매 요청 반복되는 시스템 지시문과 도구 정의다. 접두사가
동일하면 재사용되지만, 앞쪽에 타임스탬프 하나만 끼어도 전부 깨진다. 공식 문서가 재사용
조건과 깨지는 조건을 규정하므로, 비용 문제를 구성 문제로 특정할 수 있다.

## 프로젝트에 적용할 기준

- 고정 내용(지시문, 예시, 도구 정의, 스키마)을 프롬프트 앞쪽에 두고 가변 내용(사용자 입력, 요청 식별자)을 뒤에 둔다.
- 재사용하려는 접두사는 내용·순서·설정이 요청 간에 완전히 같아야 한다. 도구 정의와 순서, 스키마 키까지 포함된다.
- 타임스탬프·사용자 ID·요청 식별자를 접두사 앞쪽에 넣지 않는다.
- 대화 이력에서 앞선 메시지를 재정렬하거나 삭제하면 접두사가 깨진다.
- 캐시 대상이 되려면 최소 토큰 수를 넘겨야 한다. 그보다 짧은 접두사는 일관되게 캐시되지 않는다.
- 도구 설명이나 파라미터 스키마를 자주 손보면 재사용률이 떨어진다. 변경을 모아서 반영한다.

## 주의할 점

- 캐시 쓰기가 재사용되지 않으면 오히려 비용이 늘어난다. 접두사를 자주 바꾸는 구성은 손해다.
- 캐시는 일정 시간 미사용 시 만료된다. 지속을 전제로 설계하지 않는다.
- 동일 캐시 키에 트래픽이 과도하면 캐시를 놓칠 수 있다.
- 지원되지 않는 위치에 캐시 표시를 넣으면 요청 자체가 거절된다.

## 에이전트가 사용할 때의 체크리스트

- 고정 내용이 프롬프트 앞쪽에, 가변 내용이 뒤쪽에 있는가?
- 접두사 앞에 타임스탬프나 요청별 값이 끼어 있지 않은가?
- 도구 정의와 순서가 요청 간에 동일한가?
- 접두사가 캐시 최소 길이를 넘는가?
- 캐시 재사용률을 근거로 비용 주장을 하고 있는가, 추정인가?
