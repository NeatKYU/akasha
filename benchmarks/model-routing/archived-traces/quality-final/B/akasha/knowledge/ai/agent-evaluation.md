# 에이전트 워크플로 평가 기준

- URL: https://developers.openai.com/api/docs/guides/agent-evals
- 소유자: OpenAI
- 권위: primary
- 라이선스 메모: 메타데이터, 링크, 짧은 출처 표기 요약만 사용한다. 원문을 복제하지 않는다.
- 사용 메모: 에이전트 오케스트레이션 평가 설계 판정에만 사용한다.
- 검토 스냅샷: `openai-agent-evals` 구조 `7955a346c2cd` 본문 `6af3fd17134b`

## 이 문서가 해당 역할에 도움이 되는 이유

멀티에이전트 구조가 나은지 판단하려면 최종 산출물만 봐서는 부족하다. 어느 단계에서 잘못된
도구를 골랐는지, 인계가 언제 일어났는지가 드러나야 원인을 특정할 수 있다. 공식 가이드는
실행 기록(trace) 단위 평가를 규정하므로 평가 설계의 빈틈을 지적할 수 있다.

## 프로젝트에 적용할 기준

- 한 번의 실행을 model 호출·도구 호출·가드레일·인계의 end-to-end 기록으로 남긴다.
- 워크플로 수준 문제는 최종 산출물이 아니라 trace 채점으로 찾는다.
- 채점 기준은 대표 trace를 먼저 살펴본 뒤 만든다. 기준부터 정하고 데이터를 맞추지 않는다.
- 채점 항목에 도구 선택의 적절성, 인계 시점, 지시·안전 정책 준수를 포함한다.
- 반복 재현이 필요해진 시점에 데이터셋과 정형 eval로 옮긴다. 처음부터 형식화하지 않는다.
- 평가 결과는 프롬프트·라우팅·가드레일 중 무엇을 바꿀지로 연결한다.

## 주의할 점

- trace 채점은 사람의 판단이 들어가므로 채점자 간 편차를 관리해야 한다.
- 지나치게 이른 형식화는 성공 조건을 이해하기 전에 지표를 고정시킨다.
- 이 문서는 평가 설계를 다룬다. 모델 선택 자체의 기준은 별도 근거가 필요하다.

## 에이전트가 사용할 때의 체크리스트

- 실행 기록이 도구 호출과 인계까지 남기는가?
- 품질 문제를 최종 산출물만으로 판단하고 있지 않은가?
- 채점 기준이 대표 trace를 본 뒤 만들어졌는가?
- 채점 항목에 도구 선택과 인계 시점이 들어 있는가?
- 평가 결과가 구체적인 변경으로 연결되는가?
