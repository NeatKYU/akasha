# 함수 참조 안정화 판단 기준

## 출처

- 출처 id: `react-usecallback`
- URL: https://react.dev/reference/react/useCallback
- 소유자: Meta
- 권위: primary
- 라이선스 메모: 메타데이터, 링크, 짧은 출처 표기 요약만 사용한다. 원문을 복제하지 않는다.
- 사용 메모: useCallback 사용 여부와 의존성 판정에만 사용한다.
- 검토 스냅샷: `react-usecallback` 구조 `5030463055d4` 본문 `be5cb037b64a`

## 이 문서가 해당 역할에 도움이 되는 이유

`useCallback`은 습관적으로 붙는 훅 중 하나다. 그런데 값어치가 있는 조건은 좁고, 조건 밖에서는
코드만 늘어난다. 공식 레퍼런스가 세 가지 유효 조건과 무효화 함정을 규정하므로 근거 없는
사용을 지적할 수 있다.

## 프로젝트에 적용할 기준

- `useCallback`은 세 경우에만 값어치가 있다 — `memo` 자식에게 함수를 넘길 때, 다른 훅의 의존성일 때, 커스텀 훅이 함수를 반환할 때.
- 함수 안에서 참조하는 모든 반응형 값을 의존성에 넣고, 배열을 인라인으로 고정 길이로 쓴다.
- state를 읽어 갱신하는 함수는 갱신 함수 형태를 써서 그 state를 의존성에서 뺀다.
- Effect에서만 쓰는 함수는 `useCallback`으로 감싸지 말고 Effect 안으로 옮긴다. 그쪽이 단순하다.
- 의존성 배열을 빠뜨리면 매 렌더 새 함수가 나와 메모이제이션이 전혀 일어나지 않는다.

## 주의할 점

- 의존성에 매 렌더 새로 만들어지는 객체가 들어가면 전체 메모이제이션이 무효가 된다.
- `useCallback`은 함수 생성을 막지 않는다. 캐시된 것을 돌려줄 뿐이다.
- React는 캐시를 버릴 수 있다. 캐시 지속을 전제로 로직을 짜지 않는다.
- 반복문이나 조건문 안에서 호출할 수 없다. 컴포넌트를 추출해 해결한다.

## 에이전트가 사용할 때의 체크리스트

- 이 `useCallback`이 세 조건 중 어디에 해당하는가?
- 자식이 실제로 `memo`로 감싸져 있는가?
- 의존성에 매 렌더 새 객체가 들어 있지 않은가?
- Effect에서만 쓰는 함수를 밖에서 감싸고 있지 않은가?
- 의존성 배열이 있는가?
