## 이 문서가 해당 역할에 도움이 되는 이유

수동 `useMemo`·`useCallback`·`memo` 지적은 React Compiler를 쓰는 프로젝트에서는 값어치가
줄거나 오히려 해가 된다. 컴파일러가 무엇을 자동화하고 무엇을 못 하는지 알아야 판정의
적용 범위를 정할 수 있다.

## 프로젝트에 적용할 기준

- 프로젝트가 React Compiler를 쓰는지 먼저 확인하고 수동 메모이제이션을 판정한다.
- 컴파일러는 연쇄 리렌더 차단, 비싼 계산 메모이제이션, `useMemo`·`useCallback`·`memo` 상당의 최적화를 자동으로 한다.
- 컴파일러가 동작하려면 코드가 Rules of React를 지켜야 한다. 규칙 위반이 있으면 그것부터 고친다.
- 컴파일러는 React 컴포넌트·훅 밖의 일반 함수를 메모이제이션하지 않는다. 여러 컴포넌트가 공유하는 비싼 계산은 React 밖에서 다룬다.
- 메모이제이션한 값이 Effect 의존성으로 쓰여 재실행을 막아야 하는 경우에는 수동 메모이제이션이 여전히 필요하다.
- 기존 코드에서 수동 메모이제이션을 걷어낼 때는 컴파일 결과가 달라질 수 있으므로 시험한 뒤 제거한다.

## 주의할 점

- 컴파일러는 컴포넌트 간에 계산 결과를 공유하지 않는다. 같은 입력으로 여러 컴포넌트가 호출하면 각각 계산한다.
- 제3자 코드는 최적화 대상이 아니다.
- "컴파일러가 있으니 수동 최적화는 전부 불필요"는 과한 결론이다. 예외를 확인한다.

## 에이전트가 사용할 때의 체크리스트

- 프로젝트가 React Compiler를 쓰는가?
- 수동 메모이제이션 지적이 컴파일러 사용 여부를 확인한 뒤 나온 것인가?
- Rules of React 위반이 먼저 해결되어 있는가?
- 컴포넌트 밖의 비싼 계산을 컴파일러가 해결해 줄 것으로 기대하고 있지 않은가?
