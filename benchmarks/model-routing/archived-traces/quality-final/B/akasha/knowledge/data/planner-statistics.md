# 플래너 통계 신뢰성 기준

## 출처

- 출처 id: `postgres-planner-stats`
- URL: https://www.postgresql.org/docs/current/planner-stats.html
- 소유자: PostgreSQL Global Development Group
- 권위: primary
- 라이선스 메모: 메타데이터, 링크, 짧은 출처 표기 요약만 사용한다. 원문을 복제하지 않는다.
- 사용 메모: 추정 행 수 오차의 원인 진단에만 사용한다.
- 검토 스냅샷: `postgres-planner-stats` 구조 `b8d99ace3ae1` 본문 `bca428a2ba99`

## 이 문서가 해당 역할에 도움이 되는 이유

실행 계획을 읽다 보면 추정 행 수와 실제 행 수가 크게 어긋나는 경우를 만난다. 원인은 대개
통계이고, 통계가 어떻게 수집되고 언제 낡는지 모르면 엉뚱한 인덱스를 추가하게 된다.
공식 문서가 수집 방식과 한계를 규정하므로 오차의 원인을 근거 있게 지목할 수 있다.

## 프로젝트에 적용할 기준

- 추정과 실제 행 수 차이가 크면 먼저 통계 최신성을 의심한다. `reltuples`·`relpages`는 실시간 갱신되지 않고 `VACUUM`·`ANALYZE`·일부 DDL에서만 갱신된다.
- 통계는 표본 추출이다. 갓 수집한 통계도 근사값이라는 전제로 읽는다.
- 특정 컬럼의 추정이 계속 어긋나면 `default_statistics_target` 또는 컬럼별 `SET STATISTICS`로 표본을 늘리는 것을 검토한다.
- 여러 조건이 상관관계를 가지면 플래너는 기본적으로 독립이라고 가정해 과소 추정한다. 상관 컬럼은 확장 통계(`CREATE STATISTICS`) 대상으로 검토한다.
- 다중 컬럼 GROUP BY·JOIN에서 추정이 나쁘면 단일 컬럼 통계만으로는 부족한 경우다.

## 주의할 점

- 확장 통계의 함수 종속성은 상수와의 단순 동등 비교와 `IN`에만 적용된다. 컬럼 간 비교, 범위 조건, `LIKE`에는 쓰이지 않는다.
- 플래너는 종속 컬럼 조건이 서로 모순인지 판단하지 못한다. `city='San Francisco' AND zip='90210'` 같은 조합을 중복 조건으로 오인할 수 있다.
- 통계 목표를 올리면 수집 시간과 계획 수립 비용이 함께 늘어난다.

## 에이전트가 사용할 때의 체크리스트

- 추정과 실제 행 수 차이를 확인했는가?
- 마지막 `ANALYZE` 이후 데이터가 크게 바뀌지 않았는가?
- 오차가 상관관계 있는 컬럼 조합에서 나오는가?
- 통계 목표를 올리기 전에 `ANALYZE` 재실행부터 시도했는가?
