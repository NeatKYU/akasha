# 통계 갱신 운영 기준

## 출처

- 출처 id: `postgres-analyze`
- URL: https://www.postgresql.org/docs/current/sql-analyze.html
- 소유자: PostgreSQL Global Development Group
- 권위: primary
- 라이선스 메모: 메타데이터, 링크, 짧은 출처 표기 요약만 사용한다. 원문을 복제하지 않는다.
- 사용 메모: ANALYZE 실행 시점과 통계 목표 조정 판정에만 사용한다.
- 검토 스냅샷: `postgres-analyze` 구조 `0d70a83c3171` 본문 `a21d98c8ed16`

## 이 문서가 해당 역할에 도움이 되는 이유

실행 계획이 갑자기 나빠지는 흔한 원인이 낡은 통계다. 그런데 autovacuum이 모든 경우를
덮지 않아서, 특정 테이블만 계속 어긋나는 상황이 생긴다. 공식 문서가 자동 처리 범위와
수동 실행이 필요한 경우를 규정한다.

## 프로젝트에 적용할 기준

- 데이터를 크게 바꾼 뒤에는 `ANALYZE`를 실행한다. autovacuum에만 맡기지 않는다.
- 파티션 테이블과 상속 부모는 autovacuum이 직접 처리하지 않는다. 수동으로 통계를 갱신한다.
- 읽기 위주 데이터베이스는 사용량이 적은 시간대에 `VACUUM`과 `ANALYZE`를 주기적으로 돌리는 구성을 검토한다.
- 특정 컬럼의 추정이 계속 어긋나면 `ALTER TABLE ... SET STATISTICS` 로 그 컬럼의 목표만 올린다.
- `WHERE`·`GROUP BY`·`ORDER BY`에 쓰이지 않는 컬럼은 통계 목표를 0으로 두어 수집을 줄일 수 있다.
- distinct 값 추정이 계속 부정확하면 `n_distinct`를 수동으로 설정하는 것을 검토한다.

## 주의할 점

- 표본 추출이므로 같은 데이터에서도 실행할 때마다 통계가 조금씩 달라진다. 드물게 계획이 바뀔 수 있다.
- 통계 목표를 올리면 분석 시간과 저장 공간이 함께 늘어난다.
- 완전히 빈 테이블에는 새 통계를 기록하지 않고 기존 통계를 유지한다.
- `ANALYZE`는 읽기 잠금만 필요하지만 인덱스 열기나 파티션 표본 수집에서 대기할 수 있다.

## 에이전트가 사용할 때의 체크리스트

- 최근 대량 변경 뒤 `ANALYZE`가 실행되었는가?
- 파티션 테이블이라면 수동 갱신이 구성되어 있는가?
- 추정 오차가 특정 컬럼에 몰려 있다면 그 컬럼의 통계 목표를 조정했는가?
- 통계 목표를 전역으로 올리기 전에 컬럼 단위 조정을 시도했는가?
