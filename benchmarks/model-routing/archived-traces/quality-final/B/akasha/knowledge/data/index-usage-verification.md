# 인덱스 사용 검증 절차

## 출처

- 출처 id: `postgres-indexes-examine`
- URL: https://www.postgresql.org/docs/current/indexes-examine.html
- 소유자: PostgreSQL Global Development Group
- 권위: primary
- 라이선스 메모: 메타데이터, 링크, 짧은 출처 표기 요약만 사용한다. 원문을 복제하지 않는다.
- 사용 메모: 인덱스 추가 제안의 효과 검증 판정에만 사용한다.
- 검토 스냅샷: `postgres-indexes-examine` 구조 `20c18ef3aec3` 본문 `3aa4baecf219`

## 이 문서가 해당 역할에 도움이 되는 이유

"인덱스를 추가하면 빨라진다"는 제안은 검증 절차 없이는 받아들일 수 없다. 공식 문서는
무엇을 먼저 실행하고 어떤 설정으로 비교하며 어떤 데이터에서 재현해야 하는지 규정하므로,
근거 없는 인덱스 제안을 절차 미이행으로 지적할 수 있다.

## 프로젝트에 적용할 기준

- 인덱스 검증 전에 대상 테이블에 `ANALYZE`를 실행한다. 통계 없이 본 실행 계획은 신뢰할 수 없다.
- `EXPLAIN`으로 인덱스가 실제로 선택되는지 확인하고, 시간 비교가 필요하면 `EXPLAIN ANALYZE`를 쓴다.
- 인덱스가 도움이 되는지 보려면 `enable_seqscan`·`enable_nestloop` 같은 플래너 설정을 꺼서 강제 비교한다.
- 검증은 운영에 가까운 실제 데이터로 한다. 인위적으로 만든 분포나 정렬된 삽입 데이터를 쓰지 않는다.
- 강제해도 개선이 없으면 인덱스가 부적합하거나 비용 추정이 부정확한 것이다. 둘 중 무엇인지 밝힌다.

## 주의할 점

- 아주 작은 테이블에서는 인덱스가 선택되지 않는 것이 정상이다. 100행 중 1행을 고르는 실험으로 결론을 내지 않는다.
- 플래너 설정을 끈 상태는 진단용이다. 그 설정을 운영에 남기지 않는다.
- 이 문서는 인덱스 사용 여부 검증을 다룬다. 실행 계획 판독 자체는 실행 계획 문서를 근거로 한다.

## 에이전트가 사용할 때의 체크리스트

- 검증 전에 `ANALYZE`를 실행했는가?
- 인덱스가 실제로 선택되는지 실행 계획으로 확인했는가?
- 플래너 설정을 꺼서 강제 비교를 해봤는가?
- 검증 데이터가 운영 분포에 가까운가?
- 개선이 없을 때 원인을 인덱스 부적합과 비용 추정 오류 중 하나로 특정했는가?
