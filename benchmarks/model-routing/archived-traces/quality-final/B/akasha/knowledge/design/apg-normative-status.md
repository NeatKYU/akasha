# 접근성 근거의 규범성 구분

## 출처

- 출처 id: `aria-apg-introduction`
- URL: https://www.w3.org/WAI/ARIA/apg/about/introduction/
- 소유자: W3C
- 권위: primary
- 라이선스 메모: 메타데이터, 링크, 짧은 출처 표기 요약만 사용한다. 원문을 복제하지 않는다.
- 사용 메모: 접근성 판정에서 규범 근거와 참고 자료를 구분할 때만 사용한다.
- 검토 스냅샷: `aria-apg-introduction` 구조 `0d6f2b0a239b` 본문 `81eef803fd05`

## 이 문서가 해당 역할에 도움이 되는 이유

이 저장소의 판정은 **위반 / 근거 있는 확인 / 근거 없음** 세 갈래다. 그런데 접근성 영역에서는
규범 표준(WCAG, ARIA)과 실무 가이드(APG)가 섞여 인용되기 쉽다. APG는 스스로를 informative로
규정하므로, 이 구분을 근거로 "위반"이라는 단어를 어디까지 쓸 수 있는지 정할 수 있다.

## 프로젝트에 적용할 기준

- WCAG와 ARIA는 규범 표준이고 APG는 informative 자료다. 위반 판정의 규범 근거로는 앞의 둘을 인용한다.
- APG 패턴을 따르지 않았다는 사실만으로 위반이라고 하지 않는다. 대신 어떤 규범 요구가 충족되지 않는지 밝힌다.
- APG 패턴에서 벗어난 설계를 검토할 때는 ARIA 명세 요구를 지키는지, 유사 패턴이나 네이티브 위젯의 키보드 관례를 따르는지 확인한다.
- APG 예제는 스타일과 동작이 일부러 다양하다. 예제를 그대로 복제해야 한다고 요구하지 않는다.

## 주의할 점

- APG는 적합성 모델이 없다. "APG 준수"라는 표현은 성립하지 않는다.
- APG는 production 코드나 디자인 시스템이 아니며 모든 접근 가능한 구현을 망라하지도 않는다.
- 이 문서는 근거의 성격을 다룬다. 구체적 요구사항은 WCAG 문서와 개별 패턴 문서를 본다.

## 에이전트가 사용할 때의 체크리스트

- 위반 판정의 근거로 규범 표준(WCAG·ARIA)을 인용했는가, 아니면 APG만 인용했는가?
- APG 패턴과 다르다는 이유만으로 위반이라고 하지 않았는가?
- APG에서 벗어난 설계라면 어떤 규범 요구를 어떻게 충족하는지 설명되어 있는가?
