# 네이티브 dialog 요소 활용 기준

## 출처

- 출처 id: `wcag22-h102-dialog`
- URL: https://www.w3.org/WAI/WCAG22/Techniques/html/H102
- 소유자: W3C
- 권위: primary
- 라이선스 메모: 메타데이터, 링크, 짧은 출처 표기 요약만 사용한다. 원문을 복제하지 않는다.
- 사용 메모: 다이얼로그를 직접 구현할지 네이티브 요소를 쓸지 판정에만 사용한다.
- 검토 스냅샷: `wcag22-h102-dialog` 구조 `a0f272fdd6fc` 본문 `97ae96f624d1`

## 이 문서가 해당 역할에 도움이 되는 이유

다이얼로그 접근성 요구사항의 상당 부분은 브라우저가 이미 구현해 두었다. 직접 만든 포커스
트랩과 inert 처리는 실수가 잦은데, 네이티브 `dialog` 요소를 `showModal()`로 열면 대부분이
해결된다. WCAG 기법 문서가 무엇이 자동이고 무엇이 저자 책임인지 규정한다.

## 프로젝트에 적용할 기준

- 모달 다이얼로그는 직접 구현하기 전에 네이티브 `dialog` + `showModal()` 사용을 먼저 검토한다.
- `showModal()`을 쓴다. `show()`는 inert 처리와 포커스 트랩을 제공하지 않는다.
- 네이티브 요소를 써도 저자가 해야 할 일이 남는다 — 첫 포커스 대상 지정, 닫기 수단 제공, `aria-labelledby`로 제목 연결.
- 검증은 네 가지로 한다 — 키보드로 열리는가, 포커스가 다이얼로그로 이동하는가, 열린 동안 포커스가 갇히는가, 닫은 뒤 호출 요소로 돌아가는가.

## 주의할 점

- `showModal()`과 `show()`의 차이가 접근성 결과를 가른다. 혼용하지 않는다.
- 네이티브 요소 사용이 접근성을 자동 보장하지 않는다. 남은 저자 책임을 확인한다.
- 브라우저 지원과 스타일링 제약이 프로젝트 요구와 맞는지 별도로 확인한다.

## 에이전트가 사용할 때의 체크리스트

- 직접 구현한 포커스 트랩이 있다면 네이티브 `dialog`를 검토했는가?
- `showModal()`을 쓰고 있는가, `show()`인가?
- 제목이 `aria-labelledby`로 연결되어 있는가?
- 네 가지 키보드 검증을 모두 확인했는가?
