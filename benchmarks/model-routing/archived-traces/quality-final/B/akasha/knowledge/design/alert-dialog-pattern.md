# 경고·확인 다이얼로그 패턴 기준

## 출처

- 출처 id: `aria-apg-alertdialog`
- URL: https://www.w3.org/WAI/ARIA/apg/patterns/alertdialog/
- 소유자: W3C
- 권위: primary
- 라이선스 메모: 메타데이터, 링크, 짧은 출처 표기 요약만 사용한다. 원문을 복제하지 않는다.
- 사용 메모: 파괴적 작업의 확인 다이얼로그 역할과 설명 연결 판정에만 사용한다.
- 검토 스냅샷: `aria-apg-alertdialog` 구조 `b1f9bc2cf004` 본문 `95a10b3a61d0`

## 이 문서가 해당 역할에 도움이 되는 이유

삭제 확인처럼 사용자 흐름을 끊고 응답을 받아야 하는 다이얼로그는 일반 다이얼로그와 역할이
다르다. 보조기술이 둘을 구분할 수 있어야 사용자가 상황의 무게를 인지한다. APG는 그 차이를
역할과 속성으로 규정하므로 잘못된 역할 선택을 지적할 수 있다.

## 프로젝트에 적용할 기준

- 사용자 흐름을 끊고 응답을 요구하는 다이얼로그는 `role="dialog"`가 아니라 `role="alertdialog"`를 쓴다.
- `aria-describedby`로 경고 메시지 요소를 가리켜 무엇을 확인하는지 보조기술이 읽게 한다.
- 모달이면 `aria-modal="true"`를 주고, 보이는 제목이 있으면 `aria-labelledby`로 이름을 붙인다.
- 키보드 조작은 모달 다이얼로그 패턴을 따른다 — 포커스 진입, Tab 트랩, Escape 닫기, 포커스 복귀.

## 주의할 점

- `aria-modal`은 바깥 상호작용을 실제로 막고 시각적으로 가린 뒤에만 붙인다.
- `aria-hidden`으로 바깥을 숨기는 옛 방식을 쓴다면 다이얼로그 자신이 그 하위에 있으면 안 된다.
- 역할만 바꾸고 키보드 동작을 갖추지 않으면 오히려 기대를 배신한다. 모달 패턴 문서와 함께 본다.

## 에이전트가 사용할 때의 체크리스트

- 파괴적 작업 확인에 `alertdialog` 역할을 썼는가?
- 경고 메시지가 `aria-describedby`로 연결되어 있는가?
- 이름과 모달 표시가 함께 있는가?
- 모달로 표시했다면 바깥이 실제로 상호작용 불가인가?
