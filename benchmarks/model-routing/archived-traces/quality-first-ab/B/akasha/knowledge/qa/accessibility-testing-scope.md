## 이 문서가 해당 역할에 도움이 되는 이유

접근성 자동 검사 통과를 적합성 증명으로 쓰는 일이 잦다. 공식 지침은 자동 도구가 찾는 것과
찾지 못하는 것을 명시하고 수동 검사를 필수로 규정하므로, "axe 통과"만 근거로 든 주장을
범위 부족으로 지적할 수 있다.

## 프로젝트에 적용할 기준

- 자동 검사만으로는 문제를 놓친다. 수동 검사를 반드시 함께 한다.
- 자동 도구가 잡는 범위는 키보드 접근성 결함, 설명적이지 않은 링크 텍스트, 색 대비, 대체 텍스트 누락, 폼 레이블 연결 정도다. 그 밖은 사람이 확인한다.
- 보조기술 사용자를 사용자 조사에 포함하고, 가능하면 직접 보조기술로 시험한다.
- public beta 전환 전에 접근성 감사를 받고 발견된 문제를 고친다.
- 새 기능을 추가할 때마다 다시 시험한다. 한 번의 통과로 끝내지 않는다.
- 기준은 WCAG 2.2 AA다. 미달은 법적 문제가 될 수 있다.

## 주의할 점

- 자동 도구 목록은 예시다. 도구 선택보다 범위 분담이 중요하다.
- 감사 통과가 이후 변경까지 보장하지 않는다.
- 이 문서는 테스트 범위를 다룬다. 자동 검사를 회귀 테스트에 넣는 방법은 접근성 회귀 문서를, 적합성 주장 형식은 WCAG 문서를 본다.

## 에이전트가 사용할 때의 체크리스트

- 접근성 주장이 자동 검사 결과에만 기대고 있지 않은가?
- 키보드 이동, 포커스 순서, 대체 텍스트 품질을 사람이 확인했는가?
- 보조기술 사용자가 조사에 포함되었는가?
- 새 기능 추가 시 재시험 계획이 있는가?
