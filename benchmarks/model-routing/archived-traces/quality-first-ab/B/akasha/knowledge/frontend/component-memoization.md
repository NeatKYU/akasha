# memo가 효과를 내는 조건

## 출처

- 출처 id: `react-memo`
- URL: https://react.dev/reference/react/memo
- 소유자: Meta
- 권위: primary
- 라이선스 메모: 메타데이터, 링크, 짧은 출처 표기 요약만 사용한다. 원문을 복제하지 않는다.
- 사용 메모: `memo` 적용의 실효성 판정에만 사용한다.
- 검토 스냅샷: `react-memo` 구조 `fb9f84118ca6` 본문 `3be48197c666`

## 이 문서가 해당 역할에 도움이 되는 이유

`memo`는 자주 붙지만 자주 무의미하다. props가 매 렌더 새로 만들어지면 얕은 비교가 항상
실패해 아무것도 막지 못한다. 공식 레퍼런스가 효과 조건과 무효 조건을 나눠 규정하므로
"붙였지만 동작하지 않는 memo"를 지적할 수 있다.

## 프로젝트에 적용할 기준

- `memo`는 같은 props로 자주 리렌더되고 렌더 비용이 비쌀 때만 효과가 있다.
- props는 원시값이거나 참조가 안정적이어야 한다. 렌더 중 만든 객체·배열·함수를 넘기면 `memo`는 무효다.
- 객체를 넘겨야 하면 `useMemo`로, 함수를 넘겨야 하면 `useCallback`으로 참조를 고정한다. 가능하면 원시값으로 쪼개 넘긴다.
- 비교는 `Object.is` 기반 얕은 비교다. 중첩 구조의 변화는 감지되지 않는다.
- 커스텀 비교 함수를 쓴다면 함수 prop을 포함해 **모든** props를 비교한다.
- 커스텀 비교에서 깊은 비교(`JSON.stringify` 등)를 하지 않는다.

## 주의할 점

- `memo`는 성능 최적화지 보장이 아니다. 자신의 state나 context가 바뀌면 그대로 리렌더된다.
- 커스텀 비교가 렌더보다 느리면 손해다. 프로파일로 확인한다.
- props 하나만 매번 바뀌어도 memo 전체가 무효가 된다.
- React Compiler 환경에서는 수동 `memo`가 불필요하다.

## 에이전트가 사용할 때의 체크리스트

- 이 컴포넌트가 같은 props로 자주 리렌더되는가?
- 넘기는 props에 렌더 중 만든 객체·배열·함수가 있는가?
- 참조 안정화 없이 `memo`만 붙이지 않았는가?
- 커스텀 비교가 있다면 모든 props를 비교하고 깊은 비교를 피하는가?
- 효과가 있다는 주장에 프로파일 근거가 있는가?
