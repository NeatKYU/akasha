- 사용 메모: 페이지 성능 주장의 지표와 임계값 판정에만 사용한다.
- 검토 스냅샷: `google-core-web-vitals` 구조 `0090d5df6812` 본문 `697e4fec0a10`

## 이 문서가 해당 역할에 도움이 되는 이유

"페이지가 빨라졌다"는 주장은 어떤 지표를 어디서 쟀는지 없이는 검증할 수 없다. Core Web
Vitals는 세 지표와 임계값, 그리고 그것이 실측 데이터라는 점을 규정하므로, 랩 측정만으로
낸 결론을 범위 문제로 지적할 수 있다.

## 프로젝트에 적용할 기준

- 성능 주장은 LCP, INP, CLS 중 어떤 지표인지 명시한다.
- 임계값은 LCP 2.5초 이내, INP 200밀리초 미만, CLS 0.1 미만이다.
- 세 지표는 실제 사용자 환경에서 수집한 필드 데이터가 기준이다. 랩 측정만으로 통과를 주장하지 않는다.
- 지표 추적은 Search Console의 보고서 같은 필드 데이터 도구로 한다.
- 성능 개선 제안에는 어느 지표를 얼마나 움직였는지 전후 수치를 남긴다.

## 주의할 점

- Core Web Vitals는 페이지 경험 요소의 일부다. 이것만으로 검색 성과가 보장되지 않는다.
- 랩 측정(Lighthouse 등)은 진단에 유용하지만 필드 데이터와 다르다. 단독 통과 기준으로 삼지 않는다.
- 임계값은 시점에 따라 바뀔 수 있다. 판정 전에 현재 기준을 확인한다.

## 에이전트가 사용할 때의 체크리스트

- 성능 주장이 어떤 지표를 가리키는가?
- 임계값과 대조한 수치가 있는가?
- 필드 데이터인가 랩 측정인가?
- 성능 개선이 검색 순위 보장으로 과장되지 않았는가?
