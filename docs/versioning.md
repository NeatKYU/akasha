# 버전 올리는 규칙

## 무엇이 버전을 결정하는가

**배포되는 것은 `akasha/` 뿐이다.** 소비 프로젝트가 설치하면 `agents/`, `knowledge/`, `skills/`
세 디렉터리만 캐시에 놓인다. 따라서 SemVer는 이 세 디렉터리의 변화만 따라간다.

```
akasha/                  ← 버전이 따라가는 대상
  agents/                    역할 = subagent_type 공개 계약
  knowledge/                 판정 근거
  skills/akasha/SKILL.md     명령과 반환 계약

scripts/  .github/  docs/  fixtures/   ← 저장소 도구. 버전을 올리지 않는다.
```

`npm run validate`를 고쳤다고 사용자에게 배포될 것이 달라지지 않는다. 그런 변경은 버전을
올리지 않는다.

## 등급

| 등급 | 신호 | 왜 |
| --- | --- | --- |
| **MAJOR** | 역할 파일 삭제·이름 변경 | `subagent_type: akasha-<역할>` 이 공개 계약이다. 사라지면 호출이 깨진다 |
| | 스킬 `name:` 변경 | `/akasha` 진입점이 바뀐다 |
| | 반환 계약 필드 제거 | 판정 결과를 소비하는 쪽이 깨진다 |
| | 설치 방식 변경 | 기존 설치본이 갱신되지 않는다 |
| **MINOR** | 역할 파일 추가 | 새 `subagent_type` 이 생긴다 |
| | 지식 문서 추가·삭제 | 판정 범위가 달라진다 |
| | 오케스트레이션 기능 추가 | 호환되지만 동작이 늘어난다 |
| **PATCH** | 지식 문서 **내용** 수정 | 근거가 정확해질 뿐 계약은 그대로다 |
| | 역할 문서 내용 수정(이름 유지) | 위와 같다 |
| | 검토 스냅샷 갱신 | 원본 재확인 기록이다 |
| **없음** | `akasha/` 밖만 변경 | 배포물이 그대로다 |

여러 등급이 섞이면 **가장 높은 등급**을 따른다.

## 확인 방법

```bash
npm run check:version              # main 대비
npm run check:version -- --base <ref>
```

변경을 분류해 필요한 등급과 실제 올린 등급을 대조한다. 부족하면 실패한다.
`npm run validate` 가 이 검사를 포함한다.

## 절차

1. `akasha/` 를 바꾼다.
2. `npm run check:version` 으로 필요한 등급을 확인한다.
3. `npm run version:set -- <새 버전>` 을 실행한다. `package.json`, lockfile, 두 매니페스트가 함께 바뀐다.
4. `CHANGELOG.md` 에 같은 버전 항목을 쓴다.
5. `docs/changes/` 에 변경 기록을 남긴다.

## 지금까지의 이탈

이 규칙을 만들기 전에 올린 버전 중 세 건이 어긋났다. 기록으로 남기고 되돌리지는 않는다 —
이미 태그된 버전을 다시 매기면 더 혼란스럽다.

| 커밋 | 올린 등급 | 규칙상 등급 | 사유 |
| --- | --- | --- | --- |
| `8ea7c25` 0.7.0 | MINOR | PATCH | 지식 문서에 검토 스냅샷 줄만 추가 |
| `f6197a5` 0.8.0 | MINOR | PATCH | 지식 문서에 `## 출처` 절만 추가. 문서·역할 증감 없음 |
| `5c9a6ca` | 없음 | PATCH | 지식 문서 재고정인데 버전을 올리지 않음 |

`akasha/` 밖 변경(카탈로그 제거, 스크립트 정리, 워크플로 교체)은 규모가 커도 버전 사유가 아니다.
0.8.0이 293개 파일을 지웠지만 배포물 관점에서는 지식 문서 내용 수정이었다.
