# 0.9.0 — 지식 문서 양식 통일과 출처 1:1 분리

2026-08-19 · 지식 문서 14개 → 27개

## 한 줄 요약

문서마다 양식이 달랐고 한 문서가 출처를 최대 5개까지 인용하고 있었다. 양식을 하나로 정해
검사로 강제하고, 출처 하나당 문서 하나로 분리했다. 그 과정에서 스텁 5개를 원문을 읽어 다시 썼다.

## 이전에는

| 상태 | 문서 수 |
| --- | ---: |
| 양식(5개 절)을 갖추고 출처 1개 | 8 |
| 양식은 갖췄으나 출처 2개 | 3 |
| 절 없이 불릿만, 출처 3~5개 | 5 |

- `frontend/runtime-baseline.md`는 출처 3개(전부 색인 페이지)에 본문 29바이트였다.
- `design/system-principles.md`는 출처 5개에 본문 26바이트였다.
- 스텁이 다른 문서가 이미 소유한 출처를 중복 인용하고 있었다(4건).
- 검토 스냅샷이 여러 개 붙어 있어 "원본이 바뀌었다"가 어느 기준을 무효화하는지 알 수 없었다.

## 이후에는

모든 문서가 같은 양식을 갖는다. `validate`가 강제한다.

```markdown
# <제목>

## 출처                              ← 반드시 첫 절, 출처 정확히 1개
## 이 문서가 해당 역할에 도움이 되는 이유
## 프로젝트에 적용할 기준                 ← 판정의 근거
## 주의할 점                           ← 오용과 한계
## 에이전트가 사용할 때의 체크리스트        ← 판정 절차
```

**문서 하나에 출처 하나**가 핵심이다. 이러면 세 가지가 1:1로 맞는다 — 검토 스냅샷이 가리키는 대상,
원본 변경 시 다시 읽을 문서, 담당 지식 선택 힌트가 약속하는 내용.

## 벤치마크 r2 공백이 메워졌다

`design`에 `aria-apg-dialog-modal`이 들어가면서 모달 접근성 판정이 가능해졌다.

- 이전: `Dialog.tsx`의 포커스 트랩·Escape 처리 → **지식베이스에 근거 없음**
- 이후: `modal-dialog-accessibility.md`의 8개 기준으로 → **위반** 판정 가능

## 원문을 읽다 발견한 것

- **`toss-tds` URL이 껍데기가 됐다.** HTTP 200이지만 헤딩 4개짜리 안내 페이지다. 수집은 성공으로
  집계되지만 지식 출처로 쓸 수 없다. 제거했다.
- **`MAX_RESPONSE_BYTES` 1MB가 너무 낮았다.** 정상 문서 4건이 크기 초과로 수집 실패하고 있었다.
  5MB로 올려 전부 수집된다.
- **`toss-design-operations`는 규범 문서가 아니다.** 형식적 기여 절차나 예외 규정이 없는 사례
  기사다. `권위: secondary`로 낮추고 "위반 판정의 단독 근거로 쓰지 않는다"를 문서에 명시했다.

## 강제 수단

| 시도 | 결과 |
| --- | --- |
| 문서에 출처 2개 이상 | `must declare exactly one source (found N)` |
| 필수 절 누락 | `must declare a "## <절>" section` |
| `## 출처`가 첫 절이 아님 | `must open with the "## 출처" section` |
| 허용 호스트 밖 URL | `assertAllowlistedUrl` 차단 |
| `권위`가 primary/secondary가 아님 | 차단 |
| 검토 스냅샷 없음 | 재검토 큐, 12건 초과 시 차단 |

## 미검증

27개 문서의 기준은 원문을 읽고 작성했으나 **사람 검토를 거치지 않았다.** 요약이 원문을 충실히
반영하는지는 CODEOWNER가 확인해야 한다. 검토 스냅샷은 작성 시점 원본에 고정되어 있으므로,
검토 후 내용을 고쳤다면 고정은 그대로 두고 본문만 바꾸면 된다.
