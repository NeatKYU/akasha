# 0.7.0 — 출처 72건 등록과 검토 부채 통제

2026-08-19 · 카탈로그 28 → 100건, 검토 모델 변경

## 한 줄 요약

출처를 3.5배로 늘리면서, 사람이 전부 검토할 수 없다는 문제를 **"매번 전부 검토"에서
"한 번 검토하고 바뀌면 다시"** 로 바꿔서 풀었다.

## 이전에는

- 지식 문서가 **어떤 시점의 출처**를 요약한 건지 기록이 없었다. 출처가 바뀌어도 알 방법이 없고,
  낡은 요약과 최신 요약을 구분할 수 없었다. 검토는 원칙적으로 매번 전부 다시 해야 했다.
- 승격 게이트가 **primary 출처 한 건이라도 실패하면 전체 중단**이었다. 출처 27건일 때는
  견딜 만했지만 99건이 되면 사실상 승격이 불가능해진다.
- 카탈로그 등록과 지식 승인의 차이가 문서로 명시돼 있지 않았다.

## 이후에는

### 1. 검토 스냅샷 고정

지식 문서가 자기가 요약한 출처의 해시를 기록한다.

```
- 출처 카탈로그: `postgres-explain`
- 검토 스냅샷: `postgres-explain@20fc66d9edfb`
```

`manifest.json`의 현재 해시와 대조해 **무엇이 낡았는지 기계가 판정**한다. 검토 대상이
"전부"에서 "바뀐 것"으로 줄어든다.

### 2. 검토 부채 상한

재검토가 필요한 문서를 큐로 모으고, **12건을 넘으면 CI가 막는다.**

```
재검토 큐 5건 (상한 12):
  - [no-source-section] akasha/knowledge/design/system-principles.md: ## 출처 절이 없어 …
```

부채를 눈에 보이게 하되 무한히 쌓이지 않게 하는 장치다. 상한을 넘으면 새 지식 문서를
추가할 수 없고 밀린 검토부터 해야 한다.

### 3. 의존성 기반 승격 게이트

**승인된 지식 문서가 실제로 인용하는 출처만** 승격을 막는다. 등록만 되고 아직 요약되지 않은
출처의 수집 실패는 승격을 막지 않는다 — 그 실패에 의존하는 판정이 없기 때문이다.

## 측정

| 지표 | 이전 | 이후 | 변화 |
| --- | ---: | ---: | ---: |
| 카탈로그 출처 | 28 | 100 | +72 |
| 승격을 막을 수 있는 출처 | 99 (전체 primary) | 27 (인용된 것만) | −73% |
| 주간 승격 성공률 (출처당 일 99% 가용 가정) | 37.0% | 76.2% | +39.2%p |
| ALLOWED_HOSTS 변경 | — | 0건 | 보안 검토 항목 없음 |
| 현재 검토 부채 | 측정 불가 | 5 / 12 | 신규 계측 |

승격 성공률은 독립 실패를 가정한 산술 추정이며 실제 관측값이 아니다.

## 강제 수단

| 시도 | 결과 |
| --- | --- |
| 출처가 바뀌었는데 재검토 안 함 | `[drifted]` 로 큐에 오름 |
| 고정을 지움 | `[unpinned]` 로 큐에 오름 |
| 인용하지 않는 출처에 고정을 붙임 | `pins a snapshot for a source it does not cite` |
| 등록되지 않은 출처를 인용 | `cites an unregistered catalog source` |
| 부채가 상한을 넘음 | `Review debt 17 exceeds ceiling 12` |

음성 테스트 5종 모두 의도대로 차단·보고됐다.

## 미검증

- **지식 문서를 만들지 않았다.** 이번 변경은 출처 등록과 검토 통제 장치까지다. 72건의 요약은
  사람이 원문을 읽고 써야 하며, 그때마다 검토 스냅샷을 고정해야 한다.
- 후보 URL은 검색으로 존재를 확인했으나 개별 fetch로 내용을 통독하지 않았다. 첫 `npm run refresh`
  실행에서 실제 수집 성공 여부가 드러난다.
- 다음 승격은 100건 전부를 수집한 새 report가 필요하다. 현재 report는 28건만 담고 있어
  `report covers 28/100 sources` 로 막힌다 — 의도된 동작이다.
