# 0.16.0+ — 역할 description 한 문장화로 always-on 절반 절감

2026-08-25 · 역할 17개

## 한 줄 요약

"명령에 따라 역할을 고르는데 왜 세션마다 다 들고 있나"에 대한 답. 세션마다 실리는 것은 역할
문서(3.3~3.9k)가 아니라 **Agent 도구 목록에 들어가는 `description` 한 줄**이었다. 세 문장을
한 문장으로 줄여 always-on을 절반으로 내렸다. 구조는 그대로다.

## 이전에는

```
description: 아카샤 스킬이 배정하는 품질보증 자문 역할. 승인된 지식 문서만 근거로 판정하고
파일을 수정하지 않는다. akasha 스킬이 구성한 팀에서만 호출한다.
```

역할당 ~90~100 tok × 17 = always-on ~1,686 tok. 뒤의 두 문장은 도구 경계(`tools:`)와 역할
문서 본문이 이미 강제하는 내용이라 목록에서는 중복이었다.

## 이후에는

```
description: akasha 스킬 전용 품질보증 자문 역할. 직접 호출하지 않는다.
```

목록에 필요한 두 가지 — 무슨 역할인지, 메인 모델이 직접 부르지 말 것 — 만 남겼다.

## 측정

| 지표 | 전 | 후 |
| --- | --- | --- |
| always-on (`claude plugin details`) | ~1,686 | **~836** (−850, −50%) |
| 역할당 always-on | ~90~100 | ~40~50 |
| akasha 스킬 always-on | ~110 | ~100 |
| on-invoke (스킬·역할) | ~11.2k / ~3.3k~3.9k | 변화 없음 |
| 부모 라우팅 읽기량 | 측정 안 함 | 측정 안 함 (description은 부모가 읽지 않는다) |

역할 10개였을 때(~1,039)보다 낮다.

## 대가

- 목록에서 "승인된 지식 문서만 근거로 판정한다"는 문구가 사라졌다. 이 제약은 역할 문서 `## 규칙`과
  `tools:` 경계가 계속 강제하므로 행동은 바뀌지 않지만, 메인 모델이 목록만 보고 역할의 성격을
  파악할 정보는 줄었다. 실전에서 메인 모델이 역할 에이전트를 직접 부르는 사례가 생기면 되돌린다.
- 남은 always-on ~836의 근본 원인은 그대로다. Claude Code는 플러그인 `agents/`를 세션 시작 때
  전부 목록에 넣고, 요청에 따라 늦게 등록하는 수단이 없다. 도메인을 안 쓰는 프로젝트에서 0으로
  만들려면 프로젝트 범위 설치(`enabledPlugins`)나 도메인별 플러그인 분리가 필요하다.

## 미검증

- 영문 description(예: `Akasha-only QA advisory role; do not call directly`)은 한국어보다 더 짧게
  토큰화될 가능성이 있으나 측정 안 함.
- 짧은 설명이 메인 모델의 오호출(역할 에이전트 직접 spawn)에 미치는 영향은 실전 표본 없음.

## 검증

`npm run validate` 통과 · `npm run check:version` MINOR/MINOR · `claude plugin details akasha@neatkyu` 실측.
