# 0.15.0+ — 지식 경로 해석 실패를 잡아서 복구

2026-08-25 · 82런 6배치

## 한 줄 요약

토큰 낭비를 찾으러 시작해서 토큰은 아무것도 입증하지 못했고, 대신 **r2 런의 20~30%가
승인된 지식 문서를 찾지 못한 채 "지식베이스에 근거 없음"으로 답하고 있던** 결함을 찾아
고쳤다. 문서는 디스크에 멀쩡히 있었다.

## 이전에는

부모가 `<플러그인 루트>`를 위치로 계산했다 — "스킬 파일이 설치된 위치의 두 단계 위".
그리고 지식 경로는 역할 문서에서 복사하도록 지시돼 있었다.

두 지점 모두에서 어긋났다.

| 실패 | 관측된 형태 | 배치 |
| --- | --- | --- |
| 루트 오인 | `.agents/skills/akasha/knowledge/...` 로 계산 | token-check, routing-index |
| 옛 문서명 재구성 | `design/system-principles.md`, `frontend/runtime-baseline.md` | knowledge-root 외 3배치 |

두 이름 모두 **0.9.0에서 삭제됐다.** 이 저장소의 실제 과거 파일명이라 모델 사전지식이
강하게 작용하고, 세 배치에서 같은 이름이 반복됐다.

어느 쪽이든 결과는 같았다. 빈 `selected_knowledge_paths`로 그대로 spawn → 자식들이 규칙대로
지식 공백 반환 → `knowledge_selection.paths`가 비어도 구조상 유효하므로 계약 검증 통과.
**조용한 오답이었다.**

`기억으로 옛 경로를 재구성하지 않는다`는 금지는 이미 SKILL.md에 있었고 세 배치 연속
지켜지지 않았다.

## 이후에는

금지 대신 **복구**다. 환각은 막지 못해도 환각의 결과는 막는다.

```
1. 확인   test -f 로 전부 확인 (역할 문서 읽는 호출에 묶어 추가 비용 0)
2. 복구   안 풀리는 경로가 있으면 → 종료가 아니라 지식 디렉터리를 나열해
          실제 파일명으로 다시 고른다. 기억과 목록이 다르면 목록이 옳다.
3. 포기   복구 후에도 팀 전체 0건일 때만 종료. 판정을 만들어 반환하지 않는다.
```

루트도 위치가 아니라 **불변식**으로 정의했다 — `knowledge/INDEX.md`와 `agents/`를 함께 가진
디렉터리. 환경변수와 "두 단계 위"는 후보를 찾는 순서로 강등했고, 후보는 쓰기 전에 확인한다.

## 측정

### 복구가 작동하는지 — 강제 조건 4런

확률 사건을 40런씩 기다리는 대신 조건을 만들었다. 역할 문서의 지식 경로를 **전부** 없는
이름으로 바꾸고, 실제 문서는 디스크에 그대로 둔 채 SKILL.md만 다르게 했다.

| 조건 | 없는 경로 시도 | 복구 | 실제 도달 문서 |
| --- | --- | --- | ---: |
| A rep1 | — | 우연히 나열 | 3 |
| **A rep2** | 시도함 | **없음** | **0** |
| B rep1 | 시도함 | `test -f` → `rg --files` | **4** |
| B rep2 | 시도함 | `test -f` → `rg --files` | **2** |

**B 2/2 복구, A 1/2 실패.** B의 전사에 절차가 그대로 찍혀 있다:

```
test -f .agents/knowledge/INDEX.md && test -d .agents/agents && echo AKASHA_ROOT_OK
test -f .agents/knowledge/design/system-principles.md || (echo DESIGN...
rg --files .agents/knowledge/design)
```

A rep2는 두 판정 모두 `knowledge_path: null`, "승인된 문서가 설치된 지식베이스 경로에 없어
판정할 수 없습니다"로 반환했다. n=2라 통계는 아니지만 확률 사건이 아니라 강제된 결정적
분기이므로 원인 귀속이 된다.

### 토큰 — 전부 판정 불가

| 배치 | 지표 | 변화 | p | MDE | 판정 |
| --- | --- | ---: | ---: | ---: | --- |
| routing-index (12런) | root_input | +14.7% | 0.318 | — | 판정 불가 |
| synthesis-reread (20런) | r2 root_input | −14.3% | 0.144 | 26.4% | 판정 불가 |
| synthesis-reread (20런) | r3 root_input | +6.5% | 0.277 | 15.7% | 판정 불가 |
| knowledge-root (40런) | r3 root_input | −13.0% | 0.051 | 18.4% | 판정 불가 |
| path-recovery (10런) | cost_usd | **+13.6%** | **0.032** | 12.35% | 대가(보정 시 미달) |

**대가**: 경로 검증(`test -f`)이 A 1/5 → B 5/5로 정착하면서 비용이 13.6% 늘었다.
유일하게 p<0.05를 통과한 값이지만, 지표 4개를 검정했으므로 Bonferroni 기준(0.0125)에는
미달한다. **"늘었을 가능성이 있다"이지 확정이 아니다.**

### 측정 도구가 지탱하지 못하는 게이트

| 범위 | 변동계수 | MDE | 15% 검출에 필요한 n |
| --- | ---: | ---: | ---: |
| r3 | 8.8% | 15.7% | 6/조건 |
| r2 | 14.9% | 26.4% | 16/조건 |
| 합산 | 23.7% | 29.7% | 40/조건 |

승격 게이트는 `15% 이상 개선`을 요구하는데 합산 검출 하한이 29.7%다. **게이트가 측정
불가능한 것을 요구하고 있다.** 합산이 범인이다 — 태스크 간 평균 차이가 분산에 섞여
변동계수가 9%에서 24%로 부풀려진다.

### 부수 수정

| 항목 | 이전 | 이후 |
| --- | --- | --- |
| `internal_errors` | 87건 (전부 codex CLI 버그) | **0건** — 게이트 정상화 |
| 효율 판정 | 눈대중 | 정확 순열검정 + MDE 라벨 |

`internal_errors === 0`은 승격 게이트다. 54런에서 잡힌 87건이 전부
`codex_models_manager: failed to renew cache TTL` 단일 CLI 버그였고, stdout 파싱 오류와
자식 오류는 전 런 0건이었다. **아카샤와 무관한 이유로 게이트가 영구히 닫혀 있었다.**

## 강제 수단

프롬프트가 아니라 검사다. 각 단언에 회귀를 주입해 실제로 걸리는 것을 확인했다.

| 시도 | 결과 |
| --- | --- |
| 루트를 위치 계산으로 되돌림 | `must define the plugin root by a checkable invariant` |
| `skills/akasha/` 배제 문구 제거 | `must reject the skill directory as the plugin root` |
| 복구 절차 제거 | `must define a knowledge path verification and recovery step` |
| 디렉터리 나열 복구 제거 | `must recover unresolvable knowledge paths by listing the real directory` |
| "목록이 옳다" 제거 | `must prefer the directory listing over remembered document names` |
| 빈 선택 차단 제거 | `must treat a team-wide empty knowledge selection as a failure` |
| 종합 단계 지식 재읽기 부활 | `must not reopen knowledge documents during root synthesis` |

## 되돌린 것

**역할 라우팅 인덱스(ROUTING.md).** 부모가 팀 구성에 27KB를 읽는다고 보고 6KB 인덱스로
줄였는데, 재보니 root_input +14.7%(p=0.318)로 판정 불가였다. 세 가지를 놓쳤다.

- 부모가 역할 문서를 한 번 훑으며 세 절과 담당 지식을 **동시에** 가져가고 있었다.
  인덱스를 도입하니 왕복이 두 번이 됐다.
- `aggregated_output`이 잘려 기록된다. 실제 25,546바이트가 916바이트로 남는다.
  즉 최초 분석의 "27KB"는 정확한 값이 아니라 하한이었고, `docs/changes/INDEX.md`가 지표로
  정의한 "부모 라우팅 읽기량(bytes)"은 이 방식으로 잴 수 없다. 신뢰할 값은
  `root_usage.input_tokens` 뿐이다.
- 검정 없이 "방향이 같으니 실제일 것"이라고 판정했다. 이 실패가 분석기에 유의성 검정을
  넣게 된 계기다.

## 미검증

- **결함 발생률 저감.** 20~30%가 0%가 됐는지는 재지 않았다. 발생률이 낮아 조건당 10런이면
  기댓값이 1~2건이고, 3/54 대 0/50을 비교해도 p≈0.24로 결론이 안 난다. 이 수정의 근거는
  통계가 아니라 **원인 규명 + 강제 조건 검증 + 검사 가드**다.
- **토큰 효과.** 여섯 배치 전부 판정 불가다. 이 작업에서 토큰 절감은 하나도 입증되지 않았다.
- **Claude Code 런타임.** 모든 측정은 Codex 하네스다. Claude Code에서는 역할 문서가 실제
  서브에이전트 시스템 프롬프트가 되므로 동작이 다를 수 있고, 그것을 잴 하네스가 없다.
