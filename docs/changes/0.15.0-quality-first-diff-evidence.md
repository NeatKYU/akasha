# 0.15.0 — diff 증거 기반 품질 우선 판정

2026-08-21 · 지식 과선택과 diff 밖 단정을 줄이는 품질 계약

## 한 줄 요약

현재 구조는 0.14.0 대비 지식 문서를 두 배 이상 읽고도 블라인드 품질이 1.17점만 올랐다.
역할별 선택 상한, 실제 diff token, 구조화 JSON hard gate를 추가하고 UNIQUE 제약 지식 공백을 메웠다.

## 이전에는

- 역할 문서는 문서 선택이 애매하면 읽는 쪽을 택했다.
- r2에서 A는 평균 2개, 현재 구조는 평균 9개 문서를 읽었지만 블라인드 품질은 1.33점 낮았다.
- diff에 없던 `alertdialog`·`aria-describedby` 제거를 단정한 실행이 있었다.
- 최종 응답의 필드 존재만 프롬프트로 요구했고, 분석기는 계약 invalid 결과도 승격할 수 있었다.
- data 역할은 schema·migration 무결성을 담당하지만 UNIQUE 제약을 직접 판정할 지식이 없었다.

## 이후에는

- 요청·scoped diff와 직접 일치하는 지식만 고르고, 애매하면 지식 공백으로 남긴다.
- 역할별 기본 2개, 독립 고위험 근거가 필요한 경우만 3번째 문서를 허용하며 4개 이상은 금지한다.
- `diff_evidence`는 변경 파일과 실제 removed/added line에 존재하는 80자 이하 토큰만 허용한다.
- 변경 전에도 없던 속성·동작은 `introduced_by_diff`가 아니라 `pre_existing`으로 분리한다.
- 부모 최종 응답은 단일 JSON 객체이며, runtime validator와 analyzer hard gate가 필드·경로·상한을 검사한다.
- PostgreSQL 공식 제약 문서로 UNIQUE 제거의 확정 효과와 요구사항·migration 공백을 분리한다.

## 측정

Codex CLI 0.147.0, `gpt-5.6-terra` medium, r2/r3 각 조건 3회, 총 12회로 0.14.0과
초기 0.15.0 후보를 비교했다. 마지막 token/path hardening 전 측정이며, 이후 변경은 별도 smoke로 검증했다.

| 지표 | 0.14.0 | 초기 0.15.0 후보 | 변화 |
| --- | ---: | ---: | ---: |
| 정규식 품질 | 61.25% | 70.83% | +9.58%p |
| 총 토큰 | 3,780,712 | 3,280,979 | -13.22% |
| 토큰 p50 | 640,371 | 535,242 | -16.42% |
| wall time p50 | 121.6초 | 115.7초 | -4.86% |
| API 환산 비용 | $2.6014 | $2.3853 | -8.31% |
| 지식 문서 Read | 52 | 33 | -36.54% |
| 역할·모델 정확도 | 100% | 100% | 동일 |

블라인드 LLM 채점자는 실제 응답에 없는 문장을 candidate에 귀속하는 오류가 반복돼 promotion
근거에서 제외했다. 따라서 목표였던 블라인드 90점은 입증하지 않았으며, 이 값은 추정하지 않는다.

마지막 hardening 뒤 r2 smoke는 핵심 접근성 회귀 3개를 잡고 기존 포커스 문제를 `pre_existing`으로
분리했으며 runtime validator를 통과했다. r3 smoke에서는 새 UNIQUE 문서가 중복 허용 효과와
migration 공백을 분리했다. 마지막 hardening 전체 12회 성능은 아직 재측정하지 않았다.

## 대가

- JSON 전용 출력은 사람이 읽을 때 Markdown보다 덜 자연스럽다.
- 강한 diff gate는 근거 없는 단정을 차단하지만, 경로 선택 실패 시 안전하게 지식 공백으로 내려 품질 recall이 낮아질 수 있다.
- 역할별 2개 상한은 토큰을 줄이지만 다중 고위험 판정에서 3번째 예외 사유 작성 비용이 생긴다.
- 지식 문서가 1개 늘어 data 역할의 선택 힌트와 on-invoke context가 소폭 증가한다.
