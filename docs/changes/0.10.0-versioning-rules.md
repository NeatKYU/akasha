## 한 줄 요약

다섯 번 연속 MINOR만 올리고 있었다. 배포 대상(`akasha/`)의 변화 종류로 등급을 정하는 규칙을
문서화하고, 그 등급을 기계가 대조하도록 만들었다.

| 커밋 | 올린 등급 | 규칙상 | 무엇이 바뀌었나 |
| --- | --- | --- | --- |

| `f6197a5` 0.8.0 | MINOR | **PATCH** | 지식 문서에 `## 출처` 절만 추가. 문서·역할 증감 없음 |
| `5c9a6ca` | 없음 | **PATCH** | 지식 문서 재고정인데 버전을 안 올림 |

0.8.0은 293개 파일을 지웠지만 **배포물 관점에서는 지식 문서 내용 수정**이었다. `catalog/`,
`reports/`, `scripts/` 는 설치되지 않으므로 사용자에게 달라진 것이 없다.

## 이후에는

### 규칙: 배포 대상만 버전을 정한다

```
akasha/                  ← 버전이 따라가는 대상
  agents/                    역할 = subagent_type 공개 계약
  knowledge/                 판정 근거
  skills/akasha/SKILL.md     명령과 반환 계약

scripts/  .github/  docs/  fixtures/   ← 저장소 도구. 버전을 올리지 않는다.
```

| 등급 | 신호 |
| --- | --- |
| MAJOR | 역할 삭제·이름 변경, 스킬 `name` 변경, 반환 계약 필드 제거, 설치 방식 변경 |
| MINOR | 역할 추가, 지식 문서 추가·삭제, 오케스트레이션 기능 추가 |
| PATCH | 지식·역할 문서 내용 수정, 검토 스냅샷 갱신 |
| 없음 | `akasha/` 밖만 변경 |

### 강제: `npm run check:version`

`akasha/` 의 diff를 분류해 필요한 등급과 실제 올린 등급을 대조한다. `npm run validate` 가 포함한다.

```
필요한 등급: MINOR
실제 올린 등급: MINOR
```

## 이 과정에서 찾은 버그 두 개

**`ajv` 유령 의존성.** 0.8.0에서 `package.json` 의 `ajv` 를 지웠는데 `scripts/lib.mjs` 의
`import Ajv2020 from 'ajv/dist/2020.js'` 가 남아 있었다. 로컬 `node_modules` 에 패키지가 남아
있어 드러나지 않았고, **새로 clone한 환경에서는 모든 스크립트가 즉시 실패**했다. 격리된 clone에서
버전 검사기를 시험하다 발견했다. 지금은 런타임 의존성이 0개다.

**`\Z` 정규식 버그.** `validateRoleKnowledgeRouting` 의 절 추출이 `(?=^## |\Z)` 를 쓰고 있었다.
JS 정규식에 `\Z` 는 없고 **리터럴 `Z`** 로 해석된다. 이번에 추가한 힌트에 `ANALYZE` 가 들어가면서
그 `Z` 에서 절이 잘렸고, 뒤따르는 힌트가 5자로 인식되어 검증이 실패했다.

이 버그는 담당 지식 힌트에 대문자 Z가 처음 등장한 순간에만 드러난다. 그 전까지는 조용히
정상 동작하는 것처럼 보였다.
