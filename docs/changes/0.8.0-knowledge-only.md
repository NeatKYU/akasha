# 0.8.0 — 지식 문서 + 원본 변경 감지만 남김

2026-08-19 · `catalog/`·`reports/`·`manifest.json`·`schema/` 제거

## 한 줄 요약

수집 파이프라인 전체가 만들어내던 durable 산출물은 **출처당 해시 2개**뿐이었다.
그 해시를 지식 문서에 직접 고정하고 나머지를 걷어냈다.

## 이전에는

```
catalog(1,120줄) → refresh → reports(276파일 1.1MB) → prepare-promotion → manifest → 지식 문서
```

각 계층이 무엇을 했는지 따져보면:

| 계층 | 담은 것 | 실제 소비자 |
| --- | --- | --- |
| `catalog/*/sources.json` | url, owner, authority, license_note, allowed_purpose | 지식 문서의 `## 출처` 절과 **전 필드 중복** |
| `reports/<날짜>/*.json` | title, description, headings, 해시 3개, http_status… | 최신 날짜 1개만 `prepare-promotion`이 읽음. 과거 날짜는 **읽는 코드 없음** |
| `manifest.json` | source_hashes | 표류 감지 |
| 배포 여부 | — | `catalog/`·`reports/` 모두 **배포되지 않음 → 에이전트가 볼 수 없음** |

`reports/`는 "격리 계층"으로 설명됐지만 `body_stored: false`라 격리할 본문이 없었고,
배포 대상이 아니라 에이전트에 도달하지도 않았다. 실제 신뢰 경계는 "사람이 요약을 쓴다"이며
그건 이 계층들과 무관하게 성립한다.

`snapshot_sha256`은 `retrieved_at`을 포함해 매 실행마다 바뀌므로 표류 감지에 쓸 수 없었다.

## 이후에는

```
지식 문서의 ## 출처  →  check-sources  →  재검토 목록
      (단일 진실 원천)      (파일 안 씀)
```

지식 문서가 자기 출처를 전부 담는다.

```
## 출처

- 출처 id: `playwright-best-practices`
- URL: https://playwright.dev/docs/best-practices
- 소유자: Microsoft
- 권위: primary
- 라이선스 메모: 메타데이터, 링크, 짧은 출처 표기 요약만 사용한다.
- 사용 메모: 브라우저 테스트 설계와 flaky test 예방 기준으로만 사용한다.
- 검토 스냅샷: `playwright-best-practices` 구조 `4759958f6b2a` 본문 `511b79b4acda`
```

`npm run check:sources`가 이 URL만 가져와 해시를 비교한다. **아무 파일도 쓰지 않고**
재검토 목록만 출력한다.

## 부수 효과 — 스텁 5개가 출처를 갖게 됐다

`catalog/`를 지우기 전에 그 메타데이터를 지식 문서로 옮겼다. 그 결과 `## 출처` 절이 없던
스텁 5개(design, frontend, product, backend, security)가 전부 URL·소유자·권위를 갖게 됐다.

이전에는 이 5개를 근거로 한 판정의 `source_url`이 항상 `null`이었다. 이제 아니다.
문서 본문이 여전히 빈약하다는 문제는 그대로지만, **출처 URL 미기록 문제는 해소됐다.**

## 잃은 것

- **요약 전 후보 사전 등록.** 0.7.0에서 등록한 72건은 지식 문서가 없으므로 함께 사라졌다.
  후보는 이제 인프라가 아니라 별도 목록으로 관리한다.
- **감사 서사.** "승인된 스냅샷에서 나왔다"는 이야기가 약해졌다. 다만 서명이 없어 증명력은
  원래도 제한적이었고, 검토 스냅샷 해시가 같은 역할을 더 적은 비용으로 한다.
- **primary 실패 시 승격 차단.** 승격할 해시 저장소가 없어져 이 게이트도 사라졌다.
  대신 `check:sources`가 가져오지 못한 출처를 매주 보고한다.

## 미검증

`check:sources`를 전체 31개 출처에 대해 실행해 구조 변경 4건·본문 변경 1건을 확인했다.
다만 그 5건의 **재검토는 하지 않았다** — 원문을 다시 읽고 요약이 유효한지 확인한 뒤
검토 스냅샷을 갱신하는 것은 사람의 일이다.
