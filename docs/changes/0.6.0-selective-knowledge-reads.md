# 0.6.0 — 담당 지식을 전부 읽지 않고 골라 읽음

2026-08-19 · 역할 서브에이전트의 지식 읽기 계약 변경

## 한 줄 요약

역할 문서가 자식에게 "담당 지식을 전부 읽으라"고 지시하고 있었고, 이 문장이 역할당 문서 수를
사실상 5~8개로 묶고 있었다. 선택 힌트를 붙여 골라 읽게 바꿔 상한을 풀었다.

## 이전에는

`## 규칙` 첫 줄이 이랬다.

> 담당 지식 문서를 **먼저 전부 읽고**, 판정마다 근거 문서 경로와 출처 URL을 남긴다.

그런데 같은 문서의 `## 실행 예산`은 읽기 도구 호출을 최대 3회로 묶고 있었다. 두 문장이 충돌한다.

- 문서 100개를 "전부" 읽으려면 읽기 3회로 불가능하다.
- 실질 지식 문서 평균이 3.4KB이므로 100개면 약 340KB ≈ 12만 토큰. 서브에이전트 하나가 감당할 양이 아니다.
- 결과적으로 역할당 문서 수가 5~8개로 묶여 있었다. 설계 의도는 선택적 읽기였는데
  계약 문장이 초기 버전부터 "전부"로 남아 있었다.
- useEffect 성능처럼 담당 범위 안이지만 문서가 없는 주제는, 에이전트가 뜨고 기존 문서를 읽은 뒤
  `지식베이스에 근거 없음`을 반환했다. 이건 의도된 동작이지만 문서를 늘려야 해결되는 문제였다.

## 이후에는

`## 담당 지식` 각 항목이 "언제 쓰는 문서인지"를 스스로 말한다.

```
## 담당 지식

경로는 packet이 전달한 `<플러그인 루트>` 절대 경로 기준이다. **이번 판정에 해당하는 문서만 골라 읽는다.**

- `knowledge/qa/e2e-test-baseline.md` — 사용자 관점 locator, 테스트 격리와 flaky 예방, web-first assertion, trace 근거
- `knowledge/qa/accessibility-regression-testing.md` — 접근성 자동 검사의 smoke 범위, 키보드 이동·focus 순서·대체 텍스트 회귀 확인
```

역할 문서가 **곧 서브에이전트의 시스템 프롬프트**이므로, 이 목록은 이미 자식의 컨텍스트에 들어 있다.
문서를 고르는 데 별도 읽기 호출이 들지 않는다 — 별도 INDEX 파일을 두는 방식보다 1회 싸다.

건너뛴 문서에 대한 안전장치도 넣었다.

> 관련 없다고 판단해 읽지 않은 문서를 근거로 판정하지 않는다. 그 문서가 다뤘을 수 있는
> 주제는 `근거 있는 확인`이 아니라 지식 공백으로 남긴다.

## 측정

| 지표 | 0.5.0 | 0.6.0 | 변화 |
| --- | ---: | ---: | ---: |
| 역할당 지식 문서 상한 | ~5–8개 | 읽기 예산과 무관 | 상한 해제 |
| 자식이 읽는 지식 문서 (2개 보유 역할) | 2개 전부 | 해당하는 것만 | 최대 −50% |
| `akasha-qa` on-invoke | ~1.6k tok | ~1.9k tok | +0.3k |
| `akasha-frontend` on-invoke | ~1.5k tok | ~1.8k tok | +0.3k |
| always-on 토큰 | ~1,039 | ~1,039 | 변화 없음 |

**on-invoke가 역할당 약 300토큰 늘었다.** 선택 힌트가 시스템 프롬프트에 들어간 대가다. 대신 자식이
읽지 않아도 되는 지식 문서(3.4KB ≈ 1.2k 토큰)마다 그만큼을 아낀다. 문서가 2개일 때는 거의 본전이고,
문서가 늘수록 이득이 커진다. 문서 10개 역할에서 2개만 고른다면 힌트 비용 약 800토큰으로
읽기 약 9.6k 토큰을 아끼는 셈이다.

즉 **이 변경의 값어치는 문서 수에 비례한다.** 지금(역할당 1~2개)은 손해에 가깝고, 문서를 늘리는
순간부터 이득으로 돌아선다.

## 강제 수단

| 항목 | 이전 | 이후 |
| --- | --- | --- |
| 항목 형식 | 없음 | `- \`path.md\` — 힌트` 형식 검사 |
| 힌트 품질 | 없음 | 10자 미만 힌트 차단 |
| 한 줄 다중 참조 | 없음 | 참조 수 = 항목 줄 수 검사 |
| 스킬 계약 | 없음 | SKILL.md의 골라 읽기 문구 검사 |

## 검증

- `npm run validate` 통과. 음성 테스트 4종이 모두 의도대로 차단
  (힌트 누락 / 힌트 과소 / 항목 줄 불일치 / 스킬 계약 이탈).
- 토큰 수치는 `claude plugin details akasha@neatkyu` 추정치.

## 미검증

골라 읽기가 **실제로 올바른 문서를 고르는지**는 측정하지 않았다. 힌트가 부실하면 자식이 관련
문서를 건너뛰고 지식 공백으로 보고할 수 있다. 역할당 문서를 늘린 뒤 선택 정확도를 재야 한다.
