# 0.16.0 — 작가 도메인 역할 7개와 첫 지식 카드 10장

2026-08-25 · 역할 10 → 17, 지식 문서 73 → 83

## 한 줄 요약

개발자 전용이던 지식베이스를 작가 도메인으로 넓혔다. 사용자가 준 작가실 역할표 10개 중 **심사가
되는 7개만** 서브에이전트로 만들고, 총괄 작가·에피소드 작가·자료 조사는 읽기 전용 심사 모델에
맞지 않아 역할로 두지 않았다. 출처 정책(primary/secondary)은 바꾸지 않았다.

## 이전에는

- 역할 10개가 전부 개발 도메인(product·design·frontend·backend·data·security·qa·platform·marketing·ai).
- 라우팅 글롭이 코드 경로 전제. 원고·설정집 경로 규약이 없었다.
- 출처 허용 호스트가 개발 문서 사이트뿐이라 국립국어원·작법 사이트를 고정할 수 없었다.

## 이후에는

| 역할 | 표의 역할 | 판정 대상 | 카드 |
| --- | --- | --- | --- |
| worldbuilding | 세계관 설계자 | 설정 문서의 완결성·정합 | 샌더슨 제1·2·3법칙 (secondary) |
| character | 캐릭터 설계자 | 시트와 원고의 행동·말투·성장 | Weiland 캐릭터 아크 (secondary) |
| plot | 플롯 설계자 | 전환점·복선·화 구성 | Weiland 이야기 구조 (secondary) |
| staging | 연출 담당 | 장면의 목표·갈등·반응 | Weiland 장면 구조 (secondary) |
| continuity | Continuity Editor | 원고 vs 설정집·시간선 | Weiland 아웃라인 + 샌더슨 제3법칙 (secondary) |
| style | 문체 편집자 | 어문 규범·표기·대사 | 국립국어원 외래어 표기 원칙·표준어 총칙 (**primary**) |
| reader | 독자 시뮬레이터 | 화 도입 훅·화 끝 질문 | Weiland 훅 (secondary, 자문 전용) |

역할로 두지 않은 셋: 총괄 작가는 부모(오케스트레이터)와 사용자, 에피소드 작가는 메인 모델의
집필, 자료 조사는 네트워크가 필요해 아카샤 밖.

작가 도메인은 지식이 두 층이다. 범용 규범(어문 규범·계약·플랫폼 규정)만 카드가 되고, 작품
고유 설정(설정집·캐릭터 시트·시간선)은 **프로젝트 문서**로 packet의 관련 파일에 실린다. 역할
문서가 이 규약을 명시한다 — continuity의 판정 기준은 지식 문서가 아니라 프로젝트 기준 문서다.

원고 경로 규약(라우팅 글롭): `world/**`, `characters/**`, `outline/**`, `episodes/**`,
`chapters/**`, `manuscript/**`, `bible/**`, `timeline/**`. 코드 역할의 글롭과 겹치지 않는다.

## 대가

- always-on +647 tok. 도메인이 하나 더 늘면 플러그인 분리를 검토해야 한다(이전 답변에서 셋을 기준으로 잡았다).
- secondary 카드 8장은 규칙대로 **위반 근거가 될 수 없다.** plot·worldbuilding·staging·reader는 "근거 있는 자문"까지만 낸다. style만 위반을 낼 수 있다.
- 한글 맞춤법(띄어쓰기·문장 부호) 카드는 이번에 못 만들었다. korean.go.kr의 page_id 1~330을 훑어 표준어 사정 원칙·외래어 표기법·표준 발음법 페이지는 찾았지만 한글 맞춤법 장 페이지는 그 범위에 없었고, 어문 규범 전용 도메인(kornorms.korean.go.kr)은 이 환경에서 접속이 안 된다.
- 실전 실행은 안 했다. 새 에이전트는 다음 세션부터 Agent 목록에 뜬다.
