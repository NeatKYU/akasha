# 0.5.0 — 역할 문서가 서브에이전트를 겸하게 됨

2026-08-19 · `akasha/roles/` → `akasha/agents/akasha-<역할>.md`

## 한 줄 요약

역할 지시문 한 벌이 Claude Code 서브에이전트 정의를 겸하게 되면서, "읽기 전용"이 프롬프트
부탁에서 **도구 경계**로 바뀌었고 부모의 진입 비용이 절반 이하로 줄었다.

## 이전에는

- `akasha/roles/*.md`는 순수 문서였다. Claude Code는 이 파일을 서브에이전트로 인식하지 못했다.
- Claude Code에서 팀을 띄우면 `general-purpose` 에이전트가 떴다 — 도구가 `*`, 즉 Write·Edit·Bash를
  모두 가진다. 역할 문서의 "읽기 작업만 한다"는 **지시일 뿐 강제되지 않았다.**
- `SKILL.md`의 실행 계약은 Codex 전용이었다. `Claude`·`Task`·`subagent_type`이 한 번도 등장하지 않았고,
  Claude Code는 "서브에이전트를 띄운다" 한 줄만 받고 나머지를 매 실행 즉흥으로 채웠다.
- 부모는 팀 구성을 위해 역할 문서 10개를 **전문으로** 읽었다.
- 반환 계약을 packet에 담아 **역할 수만큼 반복** 전달했다.

## 이후에는

- 역할 문서에 frontmatter(`name`/`description`/`tools`/`model`)가 붙어 Claude Code가 `agents/`를
  서브에이전트 디렉터리로 직접 읽는다. 파일은 여전히 한 벌이고 복제본이 없다.
- `tools: Read, Grep, Glob` — 파일 수정·커밋·셸 실행·네트워크 접근 **수단 자체가 없다.**
- `SKILL.md`에 Claude Code 호출 계약이 생겼다. 정의를 못 쓰는 환경의 fallback도 명시했다.
- 부모는 문서 전문 대신 `## 담당`·`## 호출 시점`·`## 라우팅` 블록만 범위 지정해 읽는다.
- 자식 실행 계약이 시스템 프롬프트로 이동해 packet 반복 전달이 사라졌다.

## 측정

같은 명령(`claude plugin details akasha@neatkyu`)과 같은 파일 집계로 비교했다.

| 지표 | 0.4.0 | 0.5.0 | 변화 |
| --- | ---: | ---: | ---: |
| 부모 라우팅 읽기량 | 15,943 B | 6,977 B | **−56%** |
| packet 반복 전달 (역할 5개 팀) | ~4,500 B | 0 B | **−100%** |
| always-on 토큰 | ~123 tok | ~1,039 tok | **+916 tok** |
| 스킬 on-invoke | ~6.9k tok | ~7.1k tok | +0.2k |
| 역할당 on-invoke | 측정 불가 | ~1.5–1.7k tok | 신규 계측 |

**always-on이 늘어난 것은 이번 변경의 실제 대가다.** 에이전트 10개의 description이 아카샤를
쓰지 않는 세션에도 매번 로드된다. 도구 경계와 맞바꾼 값이며, description을 줄이면 회수할 수 있다.

## 검증

- `npm run validate` 통과. 음성 테스트 6종이 모두 의도대로 실패를 발생시킴
  (Bash 부여 / model 고정 / 공용 절 분기 / name≠파일명 / prefix 누락 / frontmatter 누락).
- Claude Code 실제 로딩 확인 — `Agents (10) akasha-data, akasha-security, …`
- Codex 설치본 경로 정적 검증 — 루트 역산 일치, `roles/` 잔여 참조 0, 담당 지식 15건 전부 해석,
  미배포 대상 유출 없음.
