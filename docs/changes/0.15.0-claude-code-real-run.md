# 0.15.0+ — Claude Code 설치본 실전 실행과 전사 inspector

2026-08-25 · 실전 세션 2개(역할 5 + probe 1)

## 한 줄 요약

Codex 하네스로만 재던 아카샤를 Claude Code 설치본에서 처음 돌렸다. 하네스에서 고친 결함
(루트 오인·환각 경로)은 재현되지 않았고, 대신 런타임 실패 모드 여섯 가지와 문서 오류 하나를 찾았다.
전사를 하네스 record로 바꾸는 inspector가 생겨 실전에도 같은 가드가 걸린다.

## 이전에는

- 설치본 실행 기록이 없었다. `${CLAUDE_PLUGIN_ROOT}` 치환, 환각 경로, 도구 경계 셋 다 미검증.
- SKILL.md가 `subagent_type: akasha-<역할>`을 지시했다. 실제 값은 `akasha:akasha-<역할>`.
  모델이 알아서 맞췄기 때문에 두 세션 다 동작했지만 문서와 가드가 틀린 값을 고정하고 있었다.
- 실전 전사에서 하네스 지표(`knowledge_bypass`, `unresolved` …)를 뽑을 방법이 없었다. 이전 세션이
  남긴 초안 inspector는 첫 user 줄만 봐서 루트 해석에 실패하고 실재 경로 19개를 전부
  `hallucinated_name`으로 분류했다.

## 이후에는

- 세 항목 확정: 치환됨 / 환각 0건(n=2) / 도구 경계는 함수 노출 단계에서 강제됨.
- SKILL.md·validate 가드가 `akasha:akasha-<역할>`을 고정한다.
- `node scripts/inspect-akasha-session.mjs --session <uuid> --config-dir ~/.claude-b`가 두 세션 모두에서
  돌고, 자식 완료 여부(`run_complete`)·harness 접두어·펜스·페이징 횟수·Stop 훅 횟수·spawn 전
  부모 호출 수를 함께 낸다.

자세한 표는 [docs/handoffs/claude-code-real-run-2026-08-25.md](../handoffs/claude-code-real-run-2026-08-25.md).

## 대가

- SKILL.md +206 bytes.
- 이번 세션은 오케스트레이션과 스크립트 작성을 한 세션에서 해서 부모 측 지표가 오염됐다.
  inspector에 `*_pre_spawn` 필드를 넣어 spawn 전 구간만 따로 보게 했지만, 깨끗한 부모 표본은
  이전 세션 1개뿐이다.
- 발견한 실패 모드는 아직 fixture가 없다. 다음 A/B 전까지 SKILL.md를 바꾸지 않았다.
